# Pi Immich design

Label: wayfinder:map

## Destination

A locked design for a Rust server on a Raspberry Pi Zero 2 W that the official mobile app and the official web UI can use: the Contract, the Web UI on this server, the storage and auth model, and the relationship to the ML service, decided tightly enough that implementation can start.

## Notes

Domain language is `CONTEXT.md`. The brief is `immich-rust-pi-zero-2-spec (1).md`. The reference tree is `reference/immich` at tag v3.3.6 (`587f549f`). Sessions consult `/research`, `/grilling`, and `/domain-modeling`. This map produces decisions, not the server.

Where the official mobile app or the official web UI can see a behavior, match v3.3.6. A difference is allowed when the Pi cannot do it. [Decide which Pi constraints the app can see](issues/08-decide-which-pi-constraints-the-app-can-see.md) still holds for mobile responses. Its "no web UI" line does not: this server serves the Web UI.

Settled while charting, with the destination redrawn by [Decide whether a recipient can open a shared link](issues/14-decide-whether-a-recipient-can-open-a-shared-link.md):

- The Contract is the official mobile app's success path against server v3.3.6. The destination also includes the official web UI. Older mobile apps stay out.
- A User sees their own assets, plus albums and shared links that include them, and a partner library on the timeline as [Decide which partner responses this server matches](issues/47-decide-which-partner-responses-this-server-matches.md) decides. The first User is the admin. Several people uploading at once is out.
- An Asset is one User's photo or video. The same bytes from the same User are one Asset and one Original in object storage. Another User's copy is a separate Asset and Original. Metadata and thumbnails stay on the Pi. The server streams the Original.
- The Pi is a client of the ML service, as `reference/immich/server/src/repositories/machine-learning.repository.ts` does in v3.3.6. It `POST`s multipart to `{url}/predict` (`entries` plus `image` or `text`), pings `{url}/ping`, and tries configured URLs healthy-first. Face detection and the face embedding, CLIP, and OCR are those calls. The preview file is read from local disk. Person clustering then runs on the server by embedding distance and does not call the ML service. The default URL list is `IMMICH_MACHINE_LEARNING_URL` or `http://immich-machine-learning:3003`. The ML service has no authentication.

## Decisions so far

- [Inventory login and server info](issues/01-inventory-login-and-server-info.md) — Ping, then password or OAuth; the app never creates the first User. The session is the `immich_access_token` cookie, checked with `POST /api/auth/validateToken`.
- [Inventory upload and checksum](issues/02-inventory-upload-and-checksum.md) — Same bytes for the same User are one Asset: a backup skips when the local base64 SHA-1 already matches that User, including trash. Otherwise one multipart `POST /api/assets` (a live photo is two). The app does not send the checksum, does not read `status`, and does not resume.
- [Inventory the timeline](issues/03-inventory-the-timeline.md) — The grid is local. Remote rows arrive on `POST /api/sync/stream` with ack cursors, not a paginated asset list. A kept row is not trashed, has timeline visibility, and is the stack primary. The tile reads id, checksum, type, thumbHash, favorite, duration, live photo, stack, and edited.
- [Inventory thumbnails and originals](issues/04-inventory-thumbnails-and-originals.md) — A remote photo is `size=thumbnail`, then `size=preview`. The Original is a further request only when that viewer setting is on, or the still is animated. A remote video plays `video/playback` unless its setting asks for the Original. Seek is a player position; Android sends `Range`, and both file routes answer it with 206. A local file skips these calls.
- [Inventory albums, trash, and shared links](issues/05-inventory-albums-trash-and-shared-links.md) — Album list, album detail, and trash are local rows. The app writes them with the album routes and `DELETE /api/assets` (`force` false trashes, `force` true deletes). Shared links are their own list and edits. The app copies a `/s` or `/share` URL and never opens it.
- [Inventory how the app reads ML results](issues/06-inventory-how-the-app-reads-ml-results.md) — People, person pages, and faces on an asset are local sync rows. The only person write is `PUT /api/people/{id}` for a name or a birthday. Avatars are `GET /api/people/{id}/thumbnail`. Context and similar photos are `POST /api/search/smart`. Filename, description, and OCR text are `POST /api/search/metadata`. Face boxes are stored and not drawn. OCR boxes are drawn. No merge, hide, or face-reassign call.
- [Record ML failure behavior](issues/07-record-ml-failure-behavior.md) — Disabled is the config flags, which are what `GET /api/server/features` reports. A failed `predict` is deleted, not retried: no face, CLIP, or OCR rows are written, and clustering starts only after a new face row. The asset looks unchanged until a manual job start, or an upload thumbnail job with `notify` or `source: 'upload'`, queues the work again. Nightly work reclusters existing unassigned faces only.
- [Decide which Pi constraints the app can see](issues/08-decide-which-pi-constraints-the-app-can-see.md) — None of the eight change a success-path response. Playback streams the Original, and three in-flight uploads each return 200 or 201 with `id`.
- [Decide whether OAuth is in the Contract](issues/09-decide-whether-oauth-is-in-the-contract.md) — Password login is the only sign-in path. Features report `passwordLogin: true` and `oauth: false`. Authorize and callback are not in the Contract.
- [Decide how the first User is created](issues/10-decide-how-the-first-user-is-created.md) — Config supplies the admin email, name, and password. Startup creates that User only when none exists, refuses to start if one of the three is missing, and ignores them afterward. `POST /api/auth/admin-sign-up` is not on this server.
- [Decide what a session stores](issues/11-decide-what-a-session-stores.md) — A Session stores the SHA-256 of `immich_access_token` and the User. It lasts until logout. The cookie's Max-Age is 400 days, and only that cookie is accepted.
- [Decide whether the memory lane is in the Contract](issues/12-decide-whether-the-memory-lane-is-in-the-contract.md) — The lane, the library card, the memories list, and opening a card are in the Contract. The server generates on-this-day and birthday cards nightly, syncs them, and deletes an unsaved memory after 30 days. The memory HTTP routes stay out.
- [Inventory where rendition files live](issues/13-inventory-where-rendition-files-live.md) — Thumbnail and preview are `asset_file` rows under `thumbs`, written together by `AssetGenerateThumbnails`. The encoded video is an `encoded_video` row under `encoded-video`, written by `AssetEncodeVideo`. Playback opens that file when the row exists, and the Original when it does not.
- [Decide whether a recipient can open a shared link](issues/14-decide-whether-a-recipient-can-open-a-shared-link.md) — A recipient opens `/s/{slug}` or `/share/{key}` in the official web UI, and that open is in the destination. The mobile app still only copies the URL. The Pi still does not transcode, run models, or use Postgres, Redis, or Node at runtime, and one User uploads at a time.
- [Decide whether album activity is in the Contract](issues/15-decide-whether-album-activity-is-in-the-contract.md) — Album activity is in the Contract: the comments-and-likes switch, and likes and comments on a shared album and on an Asset in that album.
- [Decide whether face boxes are in the Contract](issues/16-decide-whether-face-boxes-are-in-the-contract.md) — A Face is one person found on an Asset: name, age, and thumbnail. Drawing the box is outside the Contract. The box, image size, and source type still travel on `AssetFaceV3` so the row can land.
- [Decide whether OCR is in the Contract](issues/17-decide-whether-ocr-is-in-the-contract.md) — The overlay and search by that text are in the Contract. The viewer draws each visible region and the selected text from `AssetOcrV1`. Search sends that text as `ocr` on `POST /api/search/metadata` when server features say `ocr`.
- [Inventory where the person thumbnail lives](issues/18-inventory-where-the-person-thumbnail-lives.md) — The GET opens `person.thumbnailPath`, written by `PersonGenerateThumbnail` at `{mediaLocation}/thumbs/{ownerId}/{personGroupId[0:2]}/{personGroupId[2:4]}/{personGroupId}.jpeg`. A missing person, an empty path, and a missing file are 404.
- [Inventory where smart-search embeddings live](issues/19-inventory-where-smart-search-embeddings-live.md) — `POST /api/search/smart` ranks `smart_search.embedding`. The text query is not stored. A missing asset row is 400. An empty table with a query vector is an empty 200 page.
- [Decide how a later User is created](issues/20-decide-how-a-later-user-is-created.md) — The admin creates each later User with `POST /api/admin/users`. Login can require a password change, no welcome mail is sent, quota is enforced, web onboarding runs, and sync makes the User invitable as an album editor.
- [Inventory which memory fields the app stores](issues/21-inventory-which-memory-fields-the-app-stores.md) — The app stores the `MemoriesV2` fields except the server's `updatedAt`, plus `memoryId` and `assetId`. The lane reads the window and the title. The list reads `isSaved`. `seenAt` is stored and not shown. A missing required field fails that sync batch.
- [Decide whether asset edits are in the Contract](issues/22-decide-whether-asset-edits-are-in-the-contract.md) — The editor is in the Contract: crop, rotate, and mirror on an owned still, and the edited thumbnail and preview the viewer then loads.
- [Decide whether this server serves the official web build](issues/23-decide-whether-this-server-serves-the-official-web-build.md) — This server serves the prebuilt v3.3.6 web app. The files are built ahead of time. The Pi does not run Node.
- [Inventory how the web UI opens a shared link](issues/24-inventory-how-the-web-ui-opens-a-shared-link.md) — Document `GET`, then config, features, and `GET /api/shared-links/me`. Password is `POST /api/shared-links/login`. An album grid is the timeline plus thumbnails. One individual Asset opens the viewer. A missing link is document 404 and API 401.
- [Inventory album activity](issues/25-inventory-album-activity.md) — The comments screen uses `GET`, `POST`, and `DELETE /api/activities`. A missing list field is an empty screen. The switch stores `isActivityEnabled` only after the album response parses. Activity is not a sync line.
- [Decide how this server stores the CLIP vector](issues/26-decide-how-this-server-stores-the-clip-vector.md) — One float32 blob per Asset in SQLite. Search ranks by exact cosine distance, then asset id, and returns the page the app already reads.
- [Inventory how the web UI creates a User](issues/27-inventory-how-the-web-ui-creates-a-user.md) — The list is `GET /api/admin/users?withDeleted=true`, create is `POST /api/admin/users`, and the detail page loads preferences, statistics, sessions, and the upload heatmap. The web gate before the library is `PUT /api/users/me`, then logout. `POST /api/auth/change-password` is the settings form.
- [Decide which memory fields this server stores](issues/28-decide-which-memory-fields-this-server-stores.md) — The memory row is the `MemoriesV2` columns, `data` included. The asset link is `memoryId` and `assetId`. `isSaved` stays false, and `seenAt` and `deletedAt` stay null, with no writer until the memory HTTP routes get one. Deletes sync `MemoryDeleteV1` and `MemoryToAssetDeleteV1`.
- [Decide whether a memory deep link is in the Contract](issues/29-decide-whether-a-memory-deep-link-is-in-the-contract.md) — The `immich://memory` link stays outside the Contract. Opening a card remains the lane and the list handing over rows they already loaded.
- [Inventory which edit fields the app stores](issues/30-inventory-which-edit-fields-the-app-stores.md) — The app stores `id`, `assetId`, `action`, `parameters`, and `sequence` from `AssetEditV1`. Save is `PUT /api/assets/{id}/edits`, or `DELETE` when the list is empty. The viewer requests `edited=true`.
- [Decide whether an edited still gets a CLIP vector](issues/31-decide-whether-an-edited-still-gets-a-clip-vector.md) — The CLIP job writes a vector only when the still has one preview. Two preview files write nothing, and a vector already stored stays until a separate delete removes it.
- [Decide which preview face detection and OCR read after an edit](issues/32-decide-which-preview-face-detection-and-ocr-read-after-an-edit.md) — Face detection sends the edited preview when that file exists, otherwise the unedited preview. OCR sends the unedited preview. Saving an Edit does not run either job.
- [Decide which shared-link open responses this server matches](issues/33-decide-which-shared-link-open-responses-this-server-matches.md) — Every call on the open matches v3.3.6. Playback of one shared video is the Original, with status 200 or 206. `realtimeTranscoding` is false.
- [Decide which activity fields this server stores](issues/34-decide-which-activity-fields-this-server-stores.md) — The activity row matches v3.3.6. List, create, delete, and statistics match v3.3.6. A shared-link session gets 403 on those routes.
- [Decide whether a CLIP model change clears stored vectors](issues/35-decide-whether-a-clip-model-change-clears-stored-vectors.md) — A running config change of the CLIP model name deletes every stored vector and does not queue a rewrite. Startup deletes only when a stored length differs from the configured model's dimension.
- [Decide which later-user responses this server matches](issues/36-decide-which-later-user-responses-this-server-matches.md) — The new-user, detail, password, and onboarding responses match v3.3.6, including `PUT /api/users/me` before the library. A Session also stores the device strings and timestamps that page reads. Server `isOnboarded` starts true, so the storage wizard does not run. The system-config body stays unspecified.
- [Decide which edit fields this server stores](issues/37-decide-which-edit-fields-this-server-stores.md) — One row per crop, rotate, or mirror, with the v3.3.6 columns. `isEdited` follows those rows. GET, PUT, and DELETE match v3.3.6, and the sync lines are `AssetEditV1` and `AssetEditDeleteV1`.
- [Inventory what the web UI does after a shared link is open](issues/38-inventory-what-the-web-ui-does-after-a-shared-link-is-open.md) — Download is info then archive, or one Original. Upload is `POST /api/assets` with the share query and no checksum. Slideshow, the map modal, and opening one Asset reuse the open's asset and timeline calls. Hover is the playback route. The shared-link pages do not call the activity routes.
- [Decide which shared-link actions after open this server matches](issues/39-decide-which-shared-link-actions-after-open-this-server-matches.md) — Every call after the open matches v3.3.6. An edited still's original download and its zip entry open the fullsize edited file when that row exists. The embedded Android motion Original stays out of the archive while `includeEmbeddedVideos` is false.
- [Decide how an operator sets the machine-learning URL and object-storage credentials](issues/40-decide-how-an-operator-sets-the-machine-learning-url-and-object-storage-credentials.md) — The machine-learning URL is `machineLearning.urls` on the admin config document. `GET` and `PUT /api/system-config`, and the defaults, match v3.3.6. Object-storage credentials are environment variables beside the first admin, not fields of that document.
- [Decide which user update, delete, and restore responses this server matches](issues/41-decide-which-user-update-delete-and-restore-responses-this-server-matches.md) — `PUT`, `DELETE`, and `POST .../restore` on `/api/admin/users/{id}` match v3.3.6. Password reset and PIN reset are that PUT. A soft delete sets `deletedAt`. Restore clears it. The hard-delete job removes the User and their Originals from object storage, then the web drops the row on `on_user_delete`.
- [Decide when the web editor finishes a save](issues/42-decide-when-the-web-editor-finishes-a-save.md) — The web save stays unfinished until `AssetEditReadyV2` for that Asset arrives, or until 10 seconds pass. `POST /api/faces` matches v3.3.6 and stores a manual face in the unedited photo's coordinates.
- [Decide which favorite responses this server matches](issues/43-decide-which-favorite-responses-this-server-matches.md) — The phone's `PUT /api/assets` returns 204, and the web heart's `PUT /api/assets/{id}` returns 200. Both set `asset.isFavorite`.
- [Decide which person hide and favorite responses this server matches](issues/44-decide-which-person-hide-and-favorite-responses-this-server-matches.md) — `PUT /api/people/{id}` matches v3.3.6 for `isHidden` and `isFavorite`. The phone stores both from `PeopleV1` and does not send the write.
- [Decide which person merge response this server matches](issues/45-decide-which-person-merge-response-this-server-matches.md) — `POST /api/people/merge` matches v3.3.6. The first id remains. Later ids move their faces onto that person and are deleted. The phone does not send the call.
- [Decide which face reassignment responses this server matches](issues/46-decide-which-face-reassignment-responses-this-server-matches.md) — Bulk reassign, single-face reassign, and face delete match v3.3.6. A new person is `POST /api/people` with an empty body. The phone stores the sync that follows.
- [Decide which partner responses this server matches](issues/47-decide-which-partner-responses-this-server-matches.md) — The four partner calls match v3.3.6. Create shares a library with `inTimeline` false. The recipient's PUT turns that library on for their timeline.
- [Decide which duplicate responses this server matches](issues/48-decide-which-duplicate-responses-this-server-matches.md) — The duplicate list, dismiss, and resolve match v3.3.6. A group is `asset.duplicateId`. Search is exact cosine against the stored CLIP vector.
- [Decide whether the web UI signs in with OAuth](issues/49-decide-whether-the-web-ui-signs-in-with-oauth.md) — The four OAuth calls match v3.3.6. `oauth.enabled` defaults to false, so password login stays the unconfigured path.
- [Decide which memory HTTP responses this server matches](issues/50-decide-which-memory-http-responses-this-server-matches.md) — The memory list, save, and delete match v3.3.6. `PUT` writes `isSaved`. `DELETE` removes the row.
- [Decide which shared-link columns this server stores](issues/51-decide-which-shared-link-columns-this-server-stores.md) — The shared-link row is the v3.3.6 columns. `key` is a blob. The asset pair is `assetId` and `sharedLinkId`.
- [Decide which asset and exif columns this server stores](issues/52-decide-which-asset-and-exif-columns-this-server-stores.md) — The asset and exif rows are the v3.3.6 columns. `duplicateId` is the group. Checksums and the thumbhash are blobs.
- [Decide which user, session, and system-metadata columns this server stores](issues/53-decide-which-user-session-and-system-metadata-columns-this-server-stores.md) — The user, session, and metadata rows are the v3.3.6 columns. `clusterGroupId` may be null. The session token is a blob.
- [Decide which person and face columns this server stores](issues/54-decide-which-person-and-face-columns-this-server-stores.md) — The person and face rows are the v3.3.6 columns. The public person id is `personGroupId`.
- [Decide which partner columns this server stores](issues/55-decide-which-partner-columns-this-server-stores.md) — The partner row is the v3.3.6 columns. `inTimeline` defaults to false.
- [Decide which stack responses this server matches](issues/56-decide-which-stack-responses-this-server-matches.md) — The stack calls match v3.3.6. The first Asset is the primary. The phone creates and deletes a stack.
- [Inventory which signed-in photo routes add a response](issues/57-inventory-which-signed-in-photo-routes-add-a-response.md) — The signed-in shell adds timeline, album, trash, people, tag, PIN, settings, workflow, and cluster calls. License stays with the admin fog.
- [Decide which signed-in timeline responses this server matches](issues/58-decide-which-signed-in-timeline-responses-this-server-matches.md) — The signed-in buckets and the asset, OCR, and face reads match v3.3.6. A partner is on the main timeline only when `inTimeline` is true.
- [Decide which map, places, folder, and explore responses this server matches](issues/59-decide-which-map-places-folder-and-explore-responses-this-server-matches.md) — Map markers, cities, explore, folders, large assets, and search suggestions match v3.3.6. Place order can differ without the Postgres trigram operator.
- [Decide which signed-in album responses this server matches](issues/60-decide-which-signed-in-album-responses-this-server-matches.md) — The album list, album document, and album writes match v3.3.6. Delete removes the album and leaves the assets.
- [Decide which trash and bulk asset update responses this server matches](issues/61-decide-which-trash-and-bulk-asset-update-responses-this-server-matches.md) — Trash restore and empty match v3.3.6. Emptying trash deletes the Original from object storage. `PUT /api/assets` returns 204.
- [Decide which people list responses this server matches](issues/62-decide-which-people-list-responses-this-server-matches.md) — The people list, person document, and people-user writes match v3.3.6. Name search can differ without the Postgres trigram operator. Sharing a person needs a cluster group.
- [Decide which tag responses this server matches](issues/63-decide-which-tag-responses-this-server-matches.md) — The tag calls match v3.3.6. A tag or exif change writes an XMP sidecar beside the Original.
- [Decide which PIN and locked-folder responses this server matches](issues/64-decide-which-pin-and-locked-folder-responses-this-server-matches.md) — PIN setup, change, reset, lock, and unlock match v3.3.6. Unlock sets `pinExpiresAt` fifteen minutes ahead. Lock clears it. Elevated permission is that expiry.
- [Decide which account-settings responses this server matches](issues/65-decide-which-account-settings-responses-this-server-matches.md) — API keys, sessions, the profile image, notifications, preferences, statistics, and the heatmap match v3.3.6. Mail is still not sent.
- [Decide which workflow and plugin responses this server matches](issues/66-decide-which-workflow-and-plugin-responses-this-server-matches.md) — Workflow and plugin calls match v3.3.6. A plugin is WASM run by Extism, and startup imports the core plugin.
- [Decide which cluster-group responses this server matches](issues/67-decide-which-cluster-group-responses-this-server-matches.md) — The cluster-group calls match v3.3.6. Creating a User still does not add a cluster, so the screen cannot load a group until one exists.
- [Decide which upload-check, job, and download responses this server matches](issues/68-decide-which-upload-check-job-and-download-responses-this-server-matches.md) — The upload check, media types, and download match v3.3.6. `transcode-video` is accepted and writes no encoded video.
- [Decide which admin jobs, maintenance, and purchase responses this server matches](issues/69-decide-which-admin-jobs-maintenance-and-purchase-responses-this-server-matches.md) — Queues, integrity, and license match v3.3.6. A backup is not a Postgres dump. The test email is not sent.
- [Decide which external-library responses this server matches](issues/70-decide-which-external-library-responses-this-server-matches.md) — The library document and the path check match v3.3.6. A scan creates no assets, and `libraryId` stays null.

## Out of scope

- The Rust binary, its cross-compile, and deployment. This map stops when the design is locked.
- Older mobile apps.
- Video transcoding. The Pi cannot do it.
- Running models on the Pi.
- Several people uploading at once.
- Postgres, Redis, and Node as runtime dependencies. The Web UI's files are built ahead of time. The Pi serves them.
