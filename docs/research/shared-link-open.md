# Shared link open

Which HTTP calls the official web UI makes when a recipient opens `/s/{slug}` or `/share/{key}`, including a password-protected link and a link that does not resolve. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565`. This is the web UI only. The mobile app does not make these calls.

The web SDK does not check the JSON against the schema. A missing field throws only when the page reads it off `null` or `undefined`. The generated client accepts only the status it declares (`oazapfts.ok`). Paths below start with `/api` because the SDK `baseUrl` is `/api` (`reference/immich/packages/sdk/src/fetch-client.ts:11`). `QS.explode` drops a query value that is `undefined` (`@oazapfts/runtime@1.0.2` `query.js`, the dependency at `reference/immich/packages/sdk/package.json:24`). `createUrl` also drops `undefined` and `null` (`reference/immich/web/src/lib/utils.ts:175-182`).

There is no `+page.server` under `web/src/routes/(user)/s` or `web/src/routes/(user)/share`. `web/src/hooks.server.ts` only rewrites font placeholders (`reference/immich/web/src/hooks.server.ts:6-10`). The document status comes from the Nest handler below.

## Sequence

**Document.** SvelteKit is a client-only app (`reference/immich/web/src/routes/+layout.ts:9-10`). The browser's first call is the page URL itself. Nest serves it for any non-API `GET` or `HEAD` whose `Accept` includes `text/html` (`reference/immich/server/src/services/api.service.ts:49-64`, `reference/immich/server/src/app.common.ts:88`). `/share/{key}` and `/s/{slug}` are matched on `request.url`, which is the path plus the query string (`api.service.ts:73-93`). The capture is the rest of that string, with no `decodeURIComponent`. A query, or another path segment such as `/photos/...`, is part of the captured key or slug, so that lookup fails and the document is 404. A normal open has neither.

A key is looked up with `validateSharedLinkKey`. Length 100 is hex; any other length is base64url (`reference/immich/server/src/services/auth.service.ts:500-509`). A slug is the captured string compared to the stored slug (`auth.service.ts:512-520`). Expired, missing, or an album link whose album is deleted fails the same check (`auth.service.ts:523-527`, `reference/immich/server/src/repositories/shared-link.repository.ts:155-173`). Any throw becomes document status 404. The body is still `index.html`, so the client still boots (`api.service.ts:66-80`, `90-99`). A password does not throw there. `getMetadataTags` returns `null` when the link has a password, the status stays 200, and the HTML placeholder is left as it is (`reference/immich/server/src/services/shared-link.service.ts:215-218`, `api.service.ts:95-99`, `reference/immich/web/src/app.html:4-5`). A link with no password gets Open Graph tags filled from the album name, or the literal `Public Share`, the description or a count, and a thumbnail URL or `/feature-panel.png` (`shared-link.service.ts:220-232`, `api.service.ts:11-25`). The page does not request that image to draw. `Cache-Control` is `no-store` (`api.service.ts:99`). If the index file cannot be read, the body is empty and nothing boots (`api.service.ts:42-47`).

**Boot.** The root load calls `init` (`+layout.ts:12-16`). That loads a bundled locale JSON, not an API route (`reference/immich/web/src/lib/utils.ts:47-54`, `reference/immich/web/src/lib/utils/i18n.ts:135-144`), then `GET /api/server/config`, then `authManager.load`, then `GET /api/server/features` unless `maintenanceMode` is true (`reference/immich/web/src/lib/utils/server.ts:10-21`). This handler always sends `maintenanceMode: false` (`reference/immich/server/src/services/server.service.ts:113-132`). A recipient with no `immich_is_authenticated` cookie makes no user call (`reference/immich/web/src/lib/managers/auth-manager.svelte.ts:50-59`, `121-133`). The user layout and the page load call `authenticate` with `public: true`, which returns after `load` and does not redirect (`reference/immich/web/src/routes/(user)/+layout.ts:5-6`, `reference/immich/web/src/lib/utils/auth.ts:13-18`, `reference/immich/web/src/lib/utils/navigation.ts:12-14`). A plain `/s/{slug}` or `/share/{key}` has no `assetId`, so `getAssetInfoFromParam` returns without a request (`navigation.ts:23-25`). It is called from the user layout and again from the page load.

**The link.** Both routes call the same `loadSharedLink` (`reference/immich/web/src/routes/(user)/s/[slug]/[[photos=photos]]/[[assetId=id]]/+page.ts:4`, `reference/immich/web/src/routes/(user)/share/[key]/[[photos=photos]]/[[assetId=id]]/+page.ts:4`). The slug route has `params.slug`. The key route has `params.key`. The other is `undefined` and is not sent. The first document load has no in-memory link, so it calls `GET /api/shared-links/me` (`reference/immich/web/src/lib/utils/shared-links.ts:27-37`). `Password required` returns the password form and stops. No asset list and no thumbnail (`shared-links.ts:56-65`, `reference/immich/web/src/lib/components/pages/SharedLinkPage.svelte:76-106`). Any other throw is the not-found page (`shared-links.ts:67`, `reference/immich/web/src/routes/(user)/s/[slug]/+error.svelte:1-5`, `reference/immich/web/src/lib/components/pages/SharedLinkErrorPage.svelte:10-14`). The same `+error.svelte` sits on the key route.

**Password submit.** `POST /api/shared-links/login` with the same `key` or `slug` query and `{ "password": "<typed>" }`. Success stores the body in memory, clears the form, and navigates in place (`SharedLinkPage.svelte:43-56`). That navigation hits `loadSharedLink` again, finds the cached link, and does not call `GET /api/shared-links/me` (`shared-links.ts:33-37`). A full reload drops the memory cache. The browser then sends the `immich_shared_link_token` cookie, and `GET /api/shared-links/me` succeeds (`shared-link.service.ts:49-61`).

**After a link with no password, or after a correct password.** `type` `ALBUM` renders `AlbumViewer`. `type` `INDIVIDUAL` renders `IndividualSharedViewer` (`SharedLinkPage.svelte:108-115`). An album grid is not the `assets` array on the link. It is `GET /api/timeline/buckets`, then `GET /api/timeline/bucket` for each month in or near the viewport, then one thumbnail `GET` per visible Asset. An individual grid is the `assets` array already on the link. The gallery then requests thumbnails for boxes in the window. No timeline call. One individual Asset and `allowUpload` false skips the grid and opens the viewer, which is part of this first paint.

## Calls

### `GET /s/{slug}` and `GET /share/{key}`

- When: the browser navigates to the URL, before any API call. This is the HTML document, not a SvelteKit server render.
- Method and path: `GET` of the page URL. No `/api` prefix. `/s/{slug}` uses the slug matcher. `/share/{key}` uses the key matcher (`api.service.ts:73-93`). `Accept` must allow `text/html`, or the handler throws 406 (`api.service.ts:59-64`).
- Request: no body. The key or slug is the path, not a query.
- Response fields the page requires: none from JSON. The body is HTML. Status 200 with no password, whether or not Open Graph tags were inserted. Status 404 when the lookup throws. The client still runs on that 404 body. A missing Open Graph title does not change the grid. The grid waits on the API calls below. The tags the server writes, when it writes them, are `description`, `og:type` `website`, `og:title`, `og:description`, and `og:image` when the image URL is non-empty (`api.service.ts:16-23`). Title is the album name or `Public Share`. Description is the link description or `{count} shared photos & videos`. The image is `/api/assets/{id}/thumbnail?key={base64url key}` or `/feature-panel.png`, resolved against the external domain (`shared-link.service.ts:222-232`).
- Source: `api.service.ts:39-100`, `shared-link.service.ts:215-232`, `auth.service.ts:500-527`. The placeholder is `app.html:4-5`.

### `GET /api/server/config`

- When: root `init`, before the link call, on every open (`server.ts:16`, `+layout.ts:12-16`).
- Method and path: `GET /api/server/config`. No query. Public (`reference/immich/server/src/controllers/server.controller.ts:114-127`, `fetch-client.ts:6767-6773`).
- Request: no body.
- Response fields the page requires: `maintenanceMode`. The handler always sends `false` (`server.service.ts:130`). `false` stays on the share URL (`+layout.ts:17-20`, `reference/immich/web/src/lib/utils/maintenance.ts:14-16`). A missing `maintenanceMode` is `undefined !== false`, so the load navigates to `/` (`maintenance.ts:14-16`, `reference/immich/web/src/lib/route.ts:158-165`). `true` navigates to `/maintenance?continue=...` and the share page does not stay up (`route.ts:73`). If this call throws, the root load keeps the error and the layout draws `ErrorLayout` instead of the share (`+layout.ts:13-24`, `reference/immich/web/src/routes/+layout.svelte:260-264`). `externalDomain` is used only for the client `og:image` meta. Missing or empty uses `location.origin` (`+layout.svelte:250-254`). The grid does not read it. The page does not read the other config fields on this path.
- Source: `server.ts:16-20`, `reference/immich/web/src/lib/managers/server-config-manager.svelte.ts:13-27`, `server.controller.ts:114-127`, `server.service.ts:113-132`.

### `GET /api/server/features`

- When: the same `init`, after config, when `maintenanceMode` is not true (`server.ts:19-21`).
- Method and path: `GET /api/server/features`. No query. Public (`server.controller.ts:99-111`, `fetch-client.ts:6778-6784`).
- Request: no body.
- Response fields the page requires: `map`, and only on an album link whose `showMetadata` is true. Missing or false hides the map button and skips the marker call (`reference/immich/web/src/lib/components/album-page/AlbumViewer.svelte:147-148`). The individual grid does not read `map`. A thrown features call is the same `ErrorLayout` as a thrown config call. The manager throws if the page reads `.value` before a successful load (`reference/immich/web/src/lib/managers/feature-flags-manager.svelte.ts:16-26`). That read happens only in the album map condition above. `realtimeTranscoding` is read only for the one-Asset video case below. Missing is falsy, so the page uses the playback URL.
- Source: `server.ts:19-21`, `feature-flags-manager.svelte.ts:13-27`, `server.controller.ts:99-111`.

### `GET /api/users/me`, `GET /api/users/me/preferences`, and sometimes `GET /api/server/about`

- When: `authManager.load` during `init`, and only when `document.cookie` contains `immich_is_authenticated` (`auth-manager.svelte.ts:50-59`, `121-133`). A recipient who is not signed in does not make these. They are not the share session. The share session is the `key` or `slug` query below. A signed-in recipient does not open a websocket unless this pair succeeds (`+layout.svelte:204-209`). The album timeline does not open one: its init returns before `connect` (`reference/immich/web/src/lib/managers/timeline-manager/timeline-manager.svelte.ts:78-84`).
- Method and path: `GET /api/users/me` and `GET /api/users/me/preferences`, together (`auth-manager.svelte.ts:62-65`, `fetch-client.ts:7617-7623`, `7732-7738`). No query. Both require a user session, not a share key (`reference/immich/server/src/controllers/user.controller.ts:55-63`, `99-107`). If `user.license.activatedAt` is missing, a third call is `GET /api/server/about` (`auth-manager.svelte.ts:68-75`, `fetch-client.ts:6745-6751`, `server.controller.ts:33-41`).
- Request: no body. The session cookie is `immich_access_token` when the client is not sending a share key (`reference/immich/server/src/services/auth.service.ts:250-269`, `485-487`, `reference/immich/server/src/enum.ts:9-14`).
- Response fields the page requires: the share page reads none of the preference body and none of the about body. It reads `user.id` only to set `isOwned` (`SharedLinkPage.svelte:36`). A missing `id` makes `isOwned` false. The grid does not change. If either of the pair throws, both results are dropped and the share load continues (`auth-manager.svelte.ts:62-81`). `authenticated` is true only when both objects are set (`auth-manager.svelte.ts:24-26`). About is ignored on failure (`auth-manager.svelte.ts:72`).
- Source: `auth-manager.svelte.ts:50-81`, `user.controller.ts:55-63`, `99-107`, `server.controller.ts:33-41`.

### `GET /api/shared-links/me?key=` or `?slug=`

- When: the page load, unless the in-memory link already has the same `key` or the same `slug` (`shared-links.ts:33-37`). That cache is why the navigation after a correct password does not call this again. A fresh document does.
- Method and path: `GET /api/shared-links/me?key={key}` on `/share/{key}`, or `GET /api/shared-links/me?slug={slug}` on `/s/{slug}` (`fetch-client.ts:7028-7040`). The client accepts only HTTP 200. The query name is `key` or `slug` (`enum.ts:31-33`). The server also accepts the headers `x-immich-share-key` and `x-immich-share-slug`. This page does not send them (`auth.service.ts:250-266`, `enum.ts:19-24`).
- Request: no body. A share key is checked before a user session (`auth.service.ts:260-266`).
- Response fields the page requires: the load reads `assets.length`, `assets[0].id` when the array is non-empty, `album.albumThumbnailAssetId` when `album` is present, `album.albumName` when `album` is present, and `description` (`shared-links.ts:42-53`). `assets` missing throws in that load. The error boundary shows the translated not-found heading plus `page.error.message` (`hooks.client.ts:6-16`, `33-36`, `SharedLinkErrorPage.svelte:10-14`). `description` missing or null uses the translated count string. `album` missing uses the translated public-share title and, if there is also no asset id, image `/feature-panel.png`. The page does not fetch that image. `password` is not read. The server copies the stored password string onto the JSON (`reference/immich/server/src/dtos/shared-link.dto.ts:103-120`). The form is not that field. It is the error below.
- Password: a stored password whose sha256 token is not in the `immich_shared_link_token` cookie is HTTP 401 and body `{ "message": "Password required" }` (`shared-link.service.ts:49-59`, `reference/immich/server/src/middleware/global-exception.filter.ts:41-62`). The filter removes `statusCode` and `error` from the JSON. The load compares `error.data.message` to that exact string and returns `passwordRequired` (`shared-links.ts:56-64`). The form is a password input and a submit button. It draws no assets (`SharedLinkPage.svelte:76-91`).
- A link that does not resolve: the same URL with a bad, expired, or deleted-album key or slug is HTTP 401 and `{ "message": "Invalid share key" }` or `{ "message": "Invalid share slug" }` (`auth.service.ts:505-519`). The load does not treat that as the password form. It throws. The page shows not-found plus that message. The document for this case was already 404. There is no separate "expired" message.
- `type` missing, after a 200, matches neither viewer. The page does not throw. It draws the title and no grid (`SharedLinkPage.svelte:108-115`). `type` `ALBUM` with `album` missing throws when the album viewer reads `album.albumName` (`AlbumViewer.svelte:33`, `79-81`). `type` `INDIVIDUAL` with `assets` an empty array and `allowUpload` false draws neither the gallery nor the viewer (`reference/immich/web/src/lib/components/share-page/IndividualSharedViewer.svelte:79-86`, `140-146`).
- The server loads every non-deleted asset on an individual link, and the album row plus its assets on an album link (`shared-link.repository.ts:73-123`). `showMetadata` false strips each asset to `id`, `type`, `originalMimeType`, `thumbhash`, `localDateTime`, `duration`, `livePhotoVideoId`, `hasMetadata` false, `width`, and `height` (`reference/immich/server/src/dtos/asset-response.dto.ts:196-209`, `shared-link.service.ts:61`). The album viewer does not paint from `album.assets`. It uses the timeline calls. Status of a found link is 200 (`shared-link.controller.ts:91-99`). A link the auth step accepted but `get` cannot find is 400 `Shared link not found` (`shared-link.service.ts:146-147`, `reference/immich/server/src/utils/misc.ts:113-116`).
- Source: `shared-links.ts:20-68`, `fetch-client.ts:7028-7040`, `shared-link.controller.ts:91-99`, `shared-link.service.ts:49-61`, `shared-link.dto.ts:103-129`, `auth.service.ts:250-276`, `500-527`.

### `POST /api/shared-links/login?key=` or `?slug=`

- When: the recipient submits the password form (`SharedLinkPage.svelte:43-65`). Not sent on first paint.
- Method and path: `POST /api/shared-links/login` with the same `key` or `slug` query as the GET (`fetch-client.ts:7008-7023`). The client accepts only HTTP 201. The controller sets no `@HttpCode` (`shared-link.controller.ts:69-88`).
- Request: JSON `{ "password": "<typed>" }` (`SharedLinkPage.svelte:45`, `shared-link.dto.ts:71-75`). The form is `novalidate` and does not reject an empty string (`SharedLinkPage.svelte:86-88`). The password is required on the schema. The page always sends the property.
- Response fields the page requires: the same reads as `GET /api/shared-links/me` once the body is assigned: `album.albumName` or the public-share title, `description` or `assets.length`, then `type` for which viewer (`SharedLinkPage.svelte:45-51`, `108-115`). `assets` missing throws in the submit handler after `passwordRequired` is already false, so the form hides and the viewer render throws on `assets.length` if `type` is `INDIVIDUAL` (`IndividualSharedViewer.svelte:35`, `79`). A wrong password is 401 `{ "message": "Invalid password" }` (`shared-link.service.ts:39-40`). The catch leaves the form up and toasts that message (`SharedLinkPage.svelte:57-58`, `reference/immich/web/src/lib/utils/handle-error.ts:38-57`). A link that is not password protected is 400 `{ "message": "Shared link is not password protected" }` (`shared-link.service.ts:35-37`). No shared link on the auth object is 403 with an empty message (`shared-link.service.ts:28-29`). The success body is the link, with metadata stripped when `showExif` is false (`shared-link.service.ts:43-45`). The handler also sets cookie `immich_shared_link_token` to the previous tokens plus the base64 sha256 of `{id}-{password}`, comma-separated, `HttpOnly`, `Path=/`, `SameSite=Lax`, `Max-Age` one day (`shared-link.controller.ts:83-88`, `shared-link.service.ts:235-236`, `reference/immich/server/src/utils/response.ts:42-67`, `enum.ts:14`). The page does not read the cookie. The browser sends it on the next same-origin `GET /api/shared-links/me`.
- Source: `SharedLinkPage.svelte:43-65`, `fetch-client.ts:7008-7023`, `shared-link.controller.ts:69-88`, `shared-link.service.ts:27-46`, `response.ts:42-67`.

### `GET /api/timeline/buckets?albumId=&order=&key=` or `&slug=`

- When: an album link has rendered. Not the password form, not an individual link, not a link that did not resolve. `Timeline` builds a `TimelineManager` and calls `updateOptions({ albumId, order })` (`AlbumViewer.svelte:36-37`, `reference/immich/web/src/lib/components/timeline/Timeline.svelte:88-90`).
- Method and path: `GET /api/timeline/buckets` (`fetch-client.ts:7524-7562`, `timeline-manager.svelte.ts:287-291`). Query is `albumId` from `album.id`, `order` from `album.order` when it is set (`asc` or `desc`, `enum.ts:75-78`), and `key` or `slug` from the route (`auth-manager.svelte.ts:17-19`). No `orderBy`. The client accepts only HTTP 200.
- Request: no body.
- Response fields the page requires: an array. Each item's `timeBucket` is passed to `Date`. A missing `timeBucket` becomes an invalid date and a month whose year and month are `NaN`. It does not throw (`timeline-manager.svelte.ts:293-301`). `count` missing becomes an undefined initial count. The title still renders. A thrown call, including a missing `album.id` (the query then has no `albumId`, the server sets the owner id and asks for `timeline.read`, and a share key is not granted that permission), is swallowed. `isInitialized` stays false, so the empty state does not show and there is no toast (`timeline.service.ts:47-59`, `reference/immich/server/src/utils/access.ts:45-49`, `145-147`, `timeline-manager.svelte.ts:78-90`, `327-334`). The album title is `album.albumName`, which is outside that call (`AlbumViewer.svelte:79-81`). An empty array sets `isInitialized` and draws the title with no months. This viewer passes no empty placeholder (`Timeline.svelte:104`, `630-633`, `AlbumViewer.svelte:76-96`). `album.assetCount` missing or `0` hides the summary, the slideshow button, and the download button. It does not stop this call (`AlbumViewer.svelte:83-85`, `129-146`, `reference/immich/web/src/lib/components/album-page/AlbumSummary.svelte:15-19`). `album.description` missing or `''` hides the description paragraph (`AlbumViewer.svelte:88`). `order` missing is omitted. The repository then sorts `desc` (`reference/immich/server/src/repositories/asset.repository.ts:808`). `album.assetCount` on a real response is the loaded album asset length (`reference/immich/server/src/dtos/album.dto.ts:257-272`).
- Source: `AlbumViewer.svelte:33-37`, `76-96`, `timeline-manager.svelte.ts:287-334`, `fetch-client.ts:7524-7562`, `timeline.controller.ts:14-23`, `timeline.service.ts:12-15`, `47-74`.

### `GET /api/timeline/bucket?timeBucket=&albumId=&order=&key=` or `&slug=`

- When: after buckets return, each month whose box is in or near the viewport (`reference/immich/web/src/lib/managers/timeline-manager/timeline-month.svelte.ts:87-97`, `reference/immich/web/src/lib/managers/timeline-manager/internal/intersection-support.svelte.ts:43-51`). One call per such month. A month that is already loaded is not requested again (`reference/immich/web/src/lib/managers/timeline-manager/internal/load-support.svelte.ts:14-26`).
- Method and path: `GET /api/timeline/bucket` (`fetch-client.ts:7479-7518`). Query adds `timeBucket` as `YYYY-MM-01T00:00:00.000Z` (`reference/immich/web/src/lib/utils/timeline-util.ts:73-76`) to the same `albumId`, `order`, and `key` or `slug`. The server returns the pre-built JSON text of the bucket (`timeline.service.ts:18-25`, `asset.repository.ts:968`). The client accepts only HTTP 200 and parses that JSON as an object.
- Request: no body. `showMetadata` false forces `withCoordinates` off. The page does not send `withCoordinates` (`timeline.service.ts:72-74`).
- Response fields the page requires: `id` must be an array. A missing `id` throws while filling the month. The month loader toasts the failure and leaves the month unloaded (`timeline-month.svelte.ts:178-180`, `321-323`, `reference/immich/web/src/lib/utils/cancellable-task.ts:142-146`). The same throw happens for a missing `duration`, `visibility`, `isFavorite`, `isImage`, `isTrashed`, `livePhotoVideoId`, `fileCreatedAt`, `localOffsetHours`, `createdAt`, `ownerId`, `projectionType`, `ratio`, or `thumbhash` array, because those are indexed directly (`timeline-month.svelte.ts:181-210`). `city`, `country`, `stack`, `latitude`, and `longitude` are optional. Missing `city` is stored as `null`. The server omits `city` and `country` when `showExif` is false, and omits `stack` because this page does not send `withStacked` (`asset.repository.ts:851-853`, `951-965`). A null `fileCreatedAt` does not throw: `DateTime.fromISO` of null is invalid, and `toObject()` on an invalid DateTime is `{}` (luxon `^3.4.4`, `reference/immich/web/package.json:54`). The thumbnail URL does not use those dates. It uses `id` and `thumbhash` (`reference/immich/web/src/lib/components/assets/thumbnail/Thumbnail.svelte:243`). `thumbhash` null omits the `c` query and skips the blur placeholder (`Thumbnail.svelte:294`). The server always selects those arrays, using `{}` when the month is empty (`asset.repository.ts:933-949`). An empty `id` draws no thumbnails for that month.
- Source: `load-support.svelte.ts:8-26`, `timeline-month.svelte.ts:87-97`, `178-210`, `321-323`, `fetch-client.ts:7479-7518`, `timeline.controller.ts:26-36`, `timeline.service.ts:18-25`, `asset.repository.ts:815-968`.

### `GET /api/assets/{id}/thumbnail?size=&edited=true&key=` or `&slug=`

- When: the grid paints. Album: each loaded Asset whose month is in or near the viewport (`Timeline.svelte:649-670`). Individual, when `allowUpload` is true or there is more than one Asset: each Asset whose justified box intersects the window (`reference/immich/web/src/lib/components/shared-components/gallery-viewer/GalleryViewer.svelte:83-87`, `343-370`). The individual assets are the `assets` from the link, passed through `toTimelineAsset` (`GalleryViewer.svelte:351`, `timeline-util.ts:133-173`). One still Asset and `allowUpload` false uses this same URL as the viewer thumbnail, then again with `size=preview` (`reference/immich/web/src/lib/components/AdaptiveImage.svelte:105-120`, `252-274`). A registered service worker may answer a later thumbnail or original `GET` from its cache. The URL the page sets does not change (`reference/immich/web/src/service-worker/index.ts:9-29`).
- Method and path: `GET /api/assets/{id}/thumbnail` (`reference/immich/packages/sdk/src/index.ts:85`, `utils.ts:234-238`). Query is `size=thumbnail` for the grid, `edited=true`, `key` or `slug`, and `c={thumbhash}` when `thumbhash` is not null. `edited` defaults to true in `getAssetMediaUrl` (`utils.ts:234-238`). The server default for a missing `edited` is false (`reference/immich/server/src/dtos/asset-media.dto.ts:21-29`). This page does not omit it. The route allows a share key (`reference/immich/server/src/controllers/asset-media.controller.ts:110-124`).
- Request: no body. The image element sets `src` to that URL (`reference/immich/web/src/lib/components/assets/thumbnail/ImageThumbnail.svelte:76-79`, `reference/immich/web/src/lib/components/Image.svelte:68-77`). An `undefined` src does not request (`Image.svelte:21-24`).
- Response fields the page requires: the body is the image bytes, not JSON. The page does not read a JSON field. A failed image shows the broken-asset placeholder and leaves the rest of the grid up (`ImageThumbnail.svelte:47-57`, `73-75`). `id` missing builds `/api/assets/undefined/thumbnail` and that request fails the same way. For an individual asset, `toTimelineAsset` reads `localDateTime`, `fileCreatedAt`, and `createdAt` with no null check (`timeline-util.ts:143-148`). A missing one does not throw (`DateTime.fromISO` of null or undefined, then `toObject()` is `{}`). `width` and `height` missing use aspect ratio 1 (`reference/immich/web/src/lib/utils/asset-utils.ts:159-161`, `reference/immich/web/src/lib/utils/layout-utils.ts:46-49`). `type` missing draws a still thumbnail, because `isVideo` is false (`timeline-util.ts:162-163`). The video element is not given a `src` until hover (`Thumbnail.svelte:255-260`, `reference/immich/web/src/lib/components/assets/thumbnail/VideoThumbnail.svelte:37-40`, `65-73`). That playback `GET` is not part of first paint.
- The one-still viewer, after the thumbnail loads or errors, requests `size=preview` on this same path (`AdaptiveImage.svelte:97-117`). When `allowDownload` is false or `showMetadata` is false, that preview URL is forced even if the preference would have asked for the Original (`utils.ts:206-210`). `size=original` is a later step, only after the preview errors or the zoom passes 1 (`AdaptiveImage.svelte:111-117`, `203-206`). It is not the first paint. `size=original` on this route is deprecated and redirects to `/api/assets/{id}/original` (`asset-media.controller.ts:127-134`).

### `GET /api/albums/{id}/map-markers?key=` or `?slug=`

- Request: no body. `id` is `album.id`.
- Response fields the page requires: none for the open. The array is stored and not read until the map button is clicked (`AlbumMap.svelte:53-60`). A throw toasts and the button stays, with an empty marker list (`AlbumMap.svelte:41-49`).

### `GET /api/assets/{id}?key=` or `?slug=`

- When: an individual link has exactly one Asset and `allowUpload` is false. The page awaits this instead of drawing the grid (`IndividualSharedViewer.svelte:140-145`). Not used for an album. Not used when `allowUpload` is true, even for one Asset: that case is the gallery above (`IndividualSharedViewer.svelte:79-86`).
- Method and path: `GET /api/assets/{id}` with `key` or `slug` (`fetch-client.ts:4859-4872`, `IndividualSharedViewer.svelte:141`). The client accepts only HTTP 200. Share keys are allowed (`reference/immich/server/src/controllers/asset.controller.ts:92-100`).
- Request: no body. `id` is `assets[0].id`.
- Response fields the page requires: the viewer reads `type`, `id`, `thumbhash`, `width`, `height`, `livePhotoVideoId`, `exifInfo.projectionType`, `originalPath`, and `hasMetadata` (`reference/immich/web/src/lib/components/asset-viewer/AssetViewer.svelte:433-452`, `471-475`). `type` missing is not a video and not a panorama, so the still viewer mounts. `id` missing builds a thumbnail URL with `undefined` and the image fails. `thumbhash` missing skips the blur and omits `c`. `width` or `height` missing uses a 1 by 1 box (`AdaptiveImage.svelte:145-150`). There is no `{:catch}`. A 400 `Asset not found`, or any other throw, leaves this branch blank (`IndividualSharedViewer.svelte:141-145`, `reference/immich/server/src/services/asset.service.ts:79-81`). `showMetadata` false returns the stripped asset (`asset.service.ts:83-85`). A shared link also drops `owner` and sets `people` to `[]` (`asset.service.ts:89-95`). The still viewer then requests the thumbnail and preview from the call above. OCR and faces are not requested, because `getSharedLink()` is set (`AssetViewer.svelte:111`, `398-409`, `shared-links.ts:41`). Stack and activity are not requested: the viewer is not given `album`, `isShared`, or `withStacked` (`AssetViewer.svelte:121-123`, `386-389`, `IndividualSharedViewer.svelte:143`).
- A video (`type` `VIDEO`) sets the player `src` to `GET /api/assets/{id}/video/playback` with `key` or `slug` and `c` when `thumbhash` is set (`reference/immich/web/src/lib/utils.ts:241-243`, `reference/immich/packages/sdk/src/index.ts:87-88`, `reference/immich/web/src/lib/components/asset-viewer/VideoNativeViewer.svelte:80-89`, `405-408`). The poster is the thumbnail URL with `size=preview` (`VideoNativeViewer.svelte:402`). If `features.realtimeTranscoding` is true, the `src` is `GET /api/assets/{id}/video/stream/main.m3u8` with the share query instead (`utils.ts:246-247`, `VideoNativeViewer.svelte:81-82`). Segment URLs are whatever that playlist lists. They are not fixed in the page. If the local preference says to play the Original, the `src` is `GET /api/assets/{id}/original` with the share query and no `size` (`VideoNativeViewer.svelte:85-86`, `utils.ts:234-238`). The playback route allows a share key (`asset-media.controller.ts:163-177`).
