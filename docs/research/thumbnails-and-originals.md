# Thumbnails and originals

Which HTTP calls the official mobile app makes to paint a thumbnail, open a photo, and play a video. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD`).

The generated Dart client is not in the checkout. These URLs are built by hand from `StoreKey.serverEndpoint`, which is the client `basePath` and already ends in `/api` (`reference/immich/mobile/lib/services/api.service.dart:115-119`, `reference/immich/mobile/lib/utils/image_url_builder.dart:5-20`). Nest mounts the controller on `assets` under the global prefix `api` (`reference/immich/server/src/enum.ts:647`, `reference/immich/server/src/app.common.ts:65`, `reference/immich/server/src/controllers/asset-media.controller.ts:43-44`). The spec paths are `/assets/{id}/thumbnail`, `/assets/{id}/original`, and `/assets/{id}/video/playback` (`reference/immich/open-api/immich-openapi-specs.json:4939`, `5026`, `5128`).

`size=$type` stringifies the generated `AssetMediaSize`. That client is not in the tree. The generator pin is 7.25.0 and the script runs `-g dart` (`reference/immich/open-api/openapitools.json:4-5`, `reference/immich/open-api/bin/generate-dart-sdk.sh:16`). That generator's stock enum `toString` returns the underlying value. The script's template patches are `api.mustache` and `native_class.mustache`, not the enum (`generate-dart-sdk.sh:11-12`). The spec's values are `original`, `fullsize`, `preview`, and `thumbnail` (`immich-openapi-specs.json:20902-20909`, `reference/immich/server/src/dtos/asset-media.dto.ts:8-17`). The app passes `AssetMediaSize.thumbnail` and `AssetMediaSize.preview`, so the query strings are `size=thumbnail` and `size=preview`.

## Sequence

**A local file skips HTTP.** `preferRemote` defaults to false (`reference/immich/mobile/lib/domain/models/config/image_config.dart:8`). A still uses the on-device file when the Asset has a local copy, the prefer-remote switch is off, and the Asset is not edited (`reference/immich/mobile/lib/presentation/widgets/images/image_provider.dart:168-180`, `226-228`). A video does the same check on its own: an existing local file, or the motion file of a live photo, is `VideoSourceType.file` and no URL is opened (`reference/immich/mobile/lib/presentation/widgets/asset_viewer/video_viewer.widget.dart:116-148`). Android passes `file.uri`, iOS passes `file.path` (`video_viewer.widget.dart:124-127`, `145-148`). The test expects that local path (`reference/immich/mobile/test/presentation/widgets/asset_viewer/video_viewer_test.dart:46-53`).

**Timeline tile.** `Thumbnail.fromAsset` uses `getThumbnailImageProvider` (`reference/immich/mobile/lib/presentation/widgets/images/thumbnail.widget.dart:34-50`). For a remote Asset with no local file, that is one GET, `size=thumbnail`. The decode size is local. `kThumbnailResolution` is 320 square and is not a query parameter (`reference/immich/mobile/lib/presentation/widgets/timeline/constants.dart:12`). The placeholder before those bytes arrive is the stored thumbhash, drawn on device, and only when the row is remote and has no local id (`thumbnail.widget.dart:44-48`).

**Opening a photo.** The viewer builds `getFullImageProvider` (`reference/immich/mobile/lib/presentation/widgets/asset_viewer/asset_page.widget.dart:356-362`). For a remote still that is not animated, the provider first shows the same thumbnail URL, then requests `size=preview`, and stops (`reference/immich/mobile/lib/presentation/widgets/images/remote_image_provider.dart:109-147`). `loadOriginal` defaults to false (`image_config.dart:8`). The Original is a third request only when that switch is on (`remote_image_provider.dart:143-157`). Pinch zoom scales the image already loaded. It does not ask for another rendition (`asset_page.widget.dart:377`). A failed photo falls back to `Thumbnail.fromAsset`, which is the thumbnail URL again (`asset_page.widget.dart:387-391`).

**Animated still.** An image whose `durationMs` is greater than 0 is `imageAnimated` (`reference/immich/mobile/lib/domain/models/asset/remote_asset.model.dart:51-52`). That viewer always requests `size=preview` and then the Original, including when `loadOriginal` is false. The comment in the provider says the preview does not animate (`remote_image_provider.dart:160-184`). If the Original bytes do not decode, it throws `StateError` after the preview was already yielded (`remote_image_provider.dart:185-191`).

**Opening a video.** The page uses `NativeVideoViewer` for anything that is not a still image, and for a live photo while its motion is playing (`asset_page.widget.dart:364`, `417-423`). The poster under the player is the same `getFullImageProvider`, so a remote video also requests the thumbnail and then `size=preview` (`asset_page.widget.dart:357-362`, `422`). The player URL is chosen once. `loadOriginalVideo` defaults to false (`reference/immich/mobile/lib/domain/models/config/viewer_config.dart:10`). Off, the path is `video/playback`. On, the path is `original`. There is no second try if that URL fails (`video_viewer.widget.dart:164-173`, `174-177`). The unit test expects `video/playback` when the local file is missing (`video_viewer_test.dart:56-62`). A live photo's player id is `livePhotoVideoId` when set, otherwise the Asset id (`video_viewer.widget.dart:166`).

**Seek.** The slider calls `seekTo` with a `Duration` (`reference/immich/mobile/lib/widgets/asset_viewer/video_controls.dart:69-77`). The provider waits 150ms, then seeks the controller to that position in milliseconds (`reference/immich/mobile/lib/providers/asset_viewer/video_player_provider.dart:108-121`). The URL does not change. No query carries the offset. The player package is pinned at `cdf621bdb7edaf996e118a58a48f6441187d79c6` (`reference/immich/mobile/pubspec.yaml:48-51`). At that commit, Android `player.seekTo` is Media3, and iOS `seekTo` is `AVPlayer.seek` with a timescale of 1000 (`android/src/main/kotlin/me/albemala/native_video_player/NativeVideoPlayerViewController.kt:125-126`, `ios/Classes/NativeVideoPlayerViewController.swift:169-176`). Android's data source is Media3 Cronet, version 1.10.0 (`reference/immich/mobile/android/gradle/libs.versions.toml:15`, `reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/MainActivity.kt:44`). Media3 adds `Range` unless the request is the whole resource from byte 0 with an unset length. The header is `bytes=<position>-` or `bytes=<position>-<end>` (`androidx.media3.datasource.HttpUtil` 1.10.0, `buildRangeRequestHeader`; `CronetDataSource` sets `HttpHeaders.RANGE` from that string). iOS does not put `Range` in the headers Immich builds. `AVPlayer.seek` is the whole expression in this repo. The server accepts `Range` on both file routes, below.

**What this path does not ask for.** The viewer never sends `size=fullsize` or `size=original` on the thumbnail route. It never adds the shared-link query `key` or `slug`. Share and download use the Original and the preview, but they are not how the viewer opens a photo or plays a video (`reference/immich/mobile/lib/repositories/asset_media.repository.dart:207`, `223`, `reference/immich/mobile/lib/repositories/download.repository.dart:87`). The edit screen is the one caller that passes `edited: false` (`reference/immich/mobile/lib/presentation/actions/edit_asset.action.dart:62`). The tile and the viewer do not. They leave `edited` at its default, `true`.

## Calls

### `GET /api/assets/{id}/thumbnail?size=thumbnail`

- When: a remote timeline tile, the viewer's placeholder before the preview, and the photo error fallback. Not used when the local-file shortcut above applies.
- Method and path: `GET /api/assets/{id}/thumbnail`. Operation `viewAsset` (`immich-openapi-specs.json:5026-5029`). Permission `asset.view`, shared links allowed (`asset-media.controller.ts:110-112`).
- Request: query `size=thumbnail`, `edited=true` on this path, and `c=` set to the thumbhash. The builder appends `c` whenever the thumbhash argument is non-null, including an empty string (`image_url_builder.dart:9-16`). The viewer passes `thumbHash ?? ""` (`image_provider.dart:189`, `220`). `edited` is the Dart bool, so the characters are `true` or `false`. The server accepts only those two, case-sensitive (`reference/immich/server/src/validation.ts:213-215`). No `Range`. No `Authorization` bearer. Android Cronet adds `Cookie` from the jar (`immich_access_token`, `immich_is_authenticated`, `immich_auth_type`) plus saved custom headers (`reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/images/RemoteImagesImpl.kt:269-274`, `reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/core/HttpClientManager.kt:65-68`, `270-279`). The engine user agent is `immich-android/<version>` (`HttpClientManager.kt:56`, `315-322`). iOS uses `URLSessionManager.shared.session`, whose cookie store holds the same cookie names and whose `User-Agent` is `immich-ios/<version>` unless a saved header replaced it (`reference/immich/mobile/ios/Runner/Images/RemoteImagesImpl.swift:38-45`, `reference/immich/mobile/ios/Runner/Core/URLSessionManager.swift:10-18`, `54-57`, `147-158`). The cache policy is `returnCacheDataElseLoad` (`RemoteImagesImpl.swift:40`).
- Response the app requires: image bytes. The loader decodes them. It does not read a JSON field (`reference/immich/mobile/lib/infrastructure/loaders/remote_image_request.dart:17-40`). The server reads `asset_file` of type `thumbnail`, prefers an edited row when `edited` is true, and `sendFile`s that path. A missing path is 404. This size is not redirected (`reference/immich/server/src/services/asset-media.service.ts:266-286`, `reference/immich/server/src/repositories/asset.repository.ts:1173-1182`, `asset-media.controller.ts:137-140`). A shared-link session forces `edited` true before that lookup (`asset-media.service.ts:262-264`).
- Source: `image_url_builder.dart:9-16`, `remote_image_provider.dart:21-27`, `thumbnail.widget.dart:34-50`. Server: `asset-media.controller.ts:110-160`, `asset-media.service.ts:251-297`.

### `GET /api/assets/{id}/thumbnail?size=preview`

- When: the remote viewer, after the thumbnail placeholder, for a still, an animated still, and the poster under a video. This is the photo the user sees when `loadOriginal` is false. The same local-file shortcut skips it.
- Method and path: `GET /api/assets/{id}/thumbnail`. Same operation as the tile. Query `size=preview` (`remote_image_provider.dart:135-141`). `edited=true` and `c=<thumbhash>` are the same as the tile.
- Request: same client, same cookies, same user agent, no `Range`. The preview request does not pass a decode size, so the platform decodes the bytes at their own size (`remote_image_provider.dart:135-142`, `remote_image_request.dart:17-22`).
- Response the app requires: image bytes, same as the tile. The server reads `asset_file` of type `preview`. A missing preview is 404. It does not fall through to the Original for this size. The fullsize fallback and the web-image redirect to `original` run only when the requested size is `fullsize` (`asset-media.service.ts:273-281`). The app does not request `fullsize` on this path.
- Source: `remote_image_provider.dart:128-144`, `160-175`. Server: `asset-media.service.ts:266-286`.

### `GET /api/assets/{id}/original`

- When: a remote still with `loadOriginal` on, every remote animated still, and a remote video whose `loadOriginalVideo` is on and whose local file is missing. The photo URL includes `edited`. The video URL does not.
- Method and path: `GET /api/assets/{id}/original`. Operation `downloadAsset` (`immich-openapi-specs.json:4939-4943`). Permission `asset.download`, shared links allowed (`asset-media.controller.ts:92-94`). Photo query is `edited=true` or, on the edit screen only, `edited=false` (`image_url_builder.dart:5-7`, `remote_image_provider.dart:154-156`). The video player builds `{endpoint}/assets/{id}/original` with no query (`video_viewer.widget.dart:164-167`). Omitted `edited` defaults to false (`reference/immich/server/src/dtos/asset.dto.ts:166-169`). A shared-link session forces edited true (`asset-media.service.ts:232-234`).
- Request: a photo uses the image loader above, so the whole body, no `Range`. A video uses the player, so Android may send `Range` as described in the sequence. iOS puts the cookie header and the saved custom headers on `AVURLAsset` and does not add `Range` itself (`video_viewer.widget.dart:169-173`, player `NativeVideoPlayerViewController.swift:63-66`). The cookie store is the one `AppDelegate` hands the player (`reference/immich/mobile/ios/Runner/AppDelegate.swift:14`). Android ignores the headers map passed into `createDataSourceFactory` and rebuilds them from `getAuthHeaders`, then sets `Cache-Control: no-store` (`HttpClientManager.kt:300-311`).
- Response the app requires: for a photo, bytes that decode; for a video, a file the player can read. No JSON. The server sends `editedPath` if that lookup found one, otherwise `originalPath` (`asset-media.service.ts:236-248`). That file is the Original on disk for this Asset, or the edited file when `edited` selects it. `sendFile` is `res.sendFile` with only `{ dotfiles: 'allow' }` (`reference/immich/server/src/utils/file.ts:47-73`). Express 5.1 `res.sendFile` passes the options through to `send` (`express` `^5.1.0` in `reference/immich/server/package.json:78`). `send` 1.1, the version Express 5.1 depends on, defaults `acceptRanges` to true, answers a single valid `bytes=` range with 206 and `Content-Range`, and answers a request with no `Range` with the whole file. The app does not branch on 200 versus 206.
- Source: `image_url_builder.dart:5-7`, `remote_image_provider.dart:143-157`, `video_viewer.widget.dart:164-173`. Server: `asset-media.controller.ts:92-108`, `asset-media.service.ts:229-248`, `file.ts:47-73`.

### `GET /api/assets/{id}/video/playback`

- When: a remote video, or a live photo's motion Asset, when `loadOriginalVideo` is false and no local file was opened. This is the default play URL.
- Method and path: `GET /api/assets/{id}/video/playback`. No query. Operation `playAssetVideo` (`immich-openapi-specs.json:5128-5131`). The description says the route supports byte range requests. Permission `asset.view`, shared links allowed (`asset-media.controller.ts:163-165`). The id is the motion Asset id for a live photo (`video_viewer.widget.dart:166-167`).
- Request: same player headers as the video Original. Android can send `Range: bytes=<position>-` or `bytes=<position>-<end>`. iOS seeks with `AVPlayer` and does not set `Range` in Immich code. There is no offset query.
- Response the app requires: a video the player can play. The server uses `encodedVideoPath` when that `asset_file` row exists, and otherwise `originalPath` (`asset-media.service.ts:300-315`, `asset.repository.ts:1186-1193`). The encoded file is not the Original. The same `sendFile` path applies, so a `Range` header is a 206 and a request without one is the whole file. A missing video Asset is 404 (`asset-media.service.ts:305-307`). The player treats a failed source as no video. It does not then open `original` (`video_viewer.widget.dart:174-177`).
- Source: `video_viewer.widget.dart:159-173`, `viewer_config.dart:8-11`. Server: `asset-media.controller.ts:163-178`, `asset-media.service.ts:300-315`.

iOS reaches the loopback proxy only after the video session has handled a client certificate or HTTP basic challenge (`URLSessionManager.swift:252-254`, `271-273`). Until then `VideoProxyServer.shared.session` is unset and the player uses `AVURLAsset` on the server URL (`NativeVideoPlayerViewController.swift:60-66`). When the proxy is running it forwards the player's headers, including `Range`, and drops `host`, `connection`, `proxy-connection`, and `keep-alive` (`VideoProxyServer.swift:98`, `157-167`).
