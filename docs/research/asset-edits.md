# Asset edits

Which HTTP calls and sync fields the v3.3.6 mobile app uses to open the editor, save a crop, rotate, or mirror, clear an edit, and show the edited still. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD` and `git rev-parse HEAD` both match). This note does not run the server or the app. The web UI's editor is not this path.

`mobile/generated/openapi` is not in the checkout, and `git ls-files` does not track it. `SyncAssetEditV1.fromJson`, `SyncAssetEditDeleteV1.fromJson`, and `AssetsApi.editAsset` are called, and their bodies are not files here. The generator pinned for that client is openapi-generator `7.25.0` (`reference/immich/open-api/openapitools.json`). The project's patch of the model template removes the debug-only required-key asserts and calls `upgradeDto` before the parse (`reference/immich/open-api/templates/mobile/serialization/native/native_class.mustache.patch`). `upgradeDto` has no entry for `SyncAssetEditV1`, `SyncAssetEditDeleteV1`, `SyncAssetV2`, `CropParameters`, `RotateParameters`, or `MirrorParameters` (`reference/immich/mobile/lib/utils/openapi_patching.dart:18-48`). A sibling generated model that is patched in this tree uses `mapValueOfType<String>(json, r'id')!` for a required string (`reference/immich/open-api/patch/asset_edit_action_item_response_dto.dart.patch:12-13`). The field lists below are the OpenAPI schema. Where a missing key throws, that is this generator's `!` on a required non-null field, not a line in the missing generated file.

The thumbnail and original URLs, and which file the server opens for `edited=true`, are already in [Thumbnails and originals](thumbnails-and-originals.md). This note says when the editor and the viewer set that flag.

## Opening the editor

The Edit action is shown only when the server is at least `2.6.0` and the selection is exactly one owned still (`reference/immich/mobile/lib/presentation/actions/edit_asset.action.dart:22-29`, `reference/immich/mobile/lib/domain/models/server_capability.model.dart:11`). `2.6.0` is `syncAssetEditsV1`. The stored version starts at `0.0.0`. A version call that returns null, or throws, leaves that number in place (`reference/immich/mobile/lib/providers/server_info.provider.dart:18-19`, `43-57`). Edit stays hidden until a version of at least `2.6.0` has been stored. Owned means `ownerId` is the signed-in user (`reference/immich/mobile/lib/utils/asset_filter.dart:9`, `reference/immich/mobile/lib/presentation/actions/action.dart:47-49`). A still here is an image that is not a live photo and not animated (`reference/immich/mobile/lib/domain/models/asset/remote_asset.model.dart:44-55`, `70`). A live photo is `livePhotoVideoId` set. An animated image is `durationMs` greater than 0. A video, a second selected asset, an asset owned by someone else, and a server older than `2.6.0` draw no Edit button.

The button does not read the file name or `projectionType`. A panorama, a GIF whose duration is null or 0, and an SVG still show Edit. The server rejects those on save, below.

Opening does not call `GET /api/assets/{id}/edits`. Nothing in `mobile/lib` calls that operation. The screen reads two local queries: `asset_edit_entity` for this asset, and the exif row (`edit_asset.action.dart:50-58`, `reference/immich/mobile/lib/infrastructure/repositories/remote_asset.repository.dart:212-217`, `67-70`). Edits are ordered by `sequence` ascending. A row whose stored action is `other` is left out. A missing exif row returns null, and the tap returns without a route (`edit_asset.action.dart:54-56`). Any throw is the toast "Failed to open the editor for the asset" (`edit_asset.action.dart:67-68`). The editor does not open.

The canvas is `getFullImageProvider(asset, edited: false)` (`edit_asset.action.dart:62`). That is the only caller that passes `edited: false`. The local-file shortcut does not look at that flag (`reference/immich/mobile/lib/presentation/widgets/images/image_provider.dart:168-180`, `226-229`). A merged asset with `isEdited` false and `preferRemote` false opens the on-device file and makes no HTTP call. A remote-only still, or a merged asset already marked edited, requests `GET /api/assets/{id}/thumbnail?size=thumbnail&edited=false`, then `size=preview&edited=false` ([Thumbnails and originals](thumbnails-and-originals.md)). The Original is requested only when the viewer's load-original switch is on, and that request also gets `edited=false`. The crop handles whichever of those images was opened.

The editor then folds the stored rows into one crop, one rotation, and two mirror flags (`reference/immich/mobile/lib/presentation/pages/edit/editor.provider.dart:24-47`, `reference/immich/mobile/lib/utils/editor.utils.dart:50-64`). It does not keep the stored sequence. Crop pixels are divided by the exif width and height (`editor.utils.dart:8-14`). Those dimensions are swapped when the orientation is `5`, `6`, `7`, `8`, `90`, or `-90` (`editor.provider.dart:29-30`, `reference/immich/mobile/lib/infrastructure/utils/exif.converter.dart:29-36`, `reference/immich/mobile/lib/data/db/main/table/remote/exif.dart:65-86`). The width and height columns are `exifImageWidth` and `exifImageHeight` from `AssetExifV1` (`reference/immich/mobile/lib/infrastructure/repositories/sync_stream.repository.dart:334-337`).

## Saving

Save is the check button, and it is disabled until something on the screen has changed (`reference/immich/mobile/lib/presentation/pages/edit/edit.page.dart:318-330`). Reset, rotate, mirror, and a crop change set that flag (`editor.provider.dart:64-65`, `94`, `105`, `111`, `122-133`). The body is built in this order, and an item is omitted when it would be a no-op (`edit.page.dart:37-59`):

- `crop`, when the pixel width or height differs from the exif width or height. `parameters` is `x`, `y`, `width`, `height`, integers (`editor.utils.dart:17-28`).
- `mirror` with `axis: horizontal`, when the horizontal flag is set.
- `mirror` with `axis: vertical`, when the vertical flag is set.
- `rotate` with `angle` equal to the angle mod 360, when that angle is not 0. The buttons step by 90 (`editor.provider.dart:109-116`).

A non-empty list is `PUT /api/assets/{id}/edits`. An empty list is `DELETE /api/assets/{id}/edits` (`reference/immich/mobile/lib/domain/services/asset.service.dart:171-176`, `reference/immich/mobile/lib/repositories/asset_api.repository.dart:81-87`). The app never sends `GET`. The controller is `assets`, under the global prefix `api` (`reference/immich/server/src/controllers/asset.controller.ts:29`, `234-269`, `reference/immich/server/src/enum.ts:647`, `reference/immich/server/src/app.common.ts:65`). The OpenAPI document declares `PUT` `200` with `AssetEditsResponseDto` and `DELETE` `204` with no body (`reference/immich/open-api/immich-openapi-specs.json:4436-4604`).

The `PUT` body is `AssetEditsCreateDto`: one required key, `edits`, an array of at least one item (`immich-openapi-specs.json:20446-20460`, `reference/immich/server/src/dtos/editing.dto.ts:112-120`). Each item is `action` and `parameters`. There is no `id` and no `sequence`. The app's `action` strings are `crop`, `rotate`, and `mirror` (`asset_api.repository.dart:115-131`).

- Crop `parameters`: `x` and `y` are integers at least 0. `width` and `height` are integers at least 1 (`editing.dto.ts:22-29`).
- Rotate `parameters`: `angle` is `0`, `90`, `180`, or `270` (`editing.dto.ts:31-42`).
- Mirror `parameters`: `axis` is `horizontal` or `vertical` (`editing.dto.ts:15-20`, `44-48`).

The server rejects a second `crop`, a second `rotate`, or a second `mirror` with the same parameters (`editing.dto.ts:100-109`). Two mirrors with different axes are allowed. The app sends at most one of each, crop first. The server also requires the crop, when present, to be the first item, and the rectangle to sit inside the asset width and height (`reference/immich/server/src/services/asset.service.ts:589-607`).

`PUT` then replaces every edit row for that asset and queues `AssetEditThumbnailGeneration` (`asset.service.ts:609-616`, `reference/immich/server/src/repositories/asset-edit.repository.ts:14-24`). `sequence` is the array index, starting at 0. `id` is generated. The returned `edits` include `id`, `action`, and `parameters`. The app does not read that body (`asset.service.dart:171-176`). The generated `editAsset` method is not in the checkout, so this note does not claim a missing response key throws. A future that throws is the error toast, the editor stays open, and the route does not pop (`edit.page.dart:69-74`). A future that completes is the success toast and `pop` (`edit.page.dart:67-68`).

The server answers `400` before it writes when the asset is missing, the type is not an image, `livePhotoVideoId` is set, `isPanorama` is true, the original path ends in `.gif` or `.svg`, or either dimension is missing (`asset.service.ts:557-587`). `isPanorama` is `projectionType === 'EQUIRECTANGULAR'` or a file name ending in `.insp` (`reference/immich/server/src/utils/asset.util.ts:236-238`). A crop that is not first, or that extends past the image, is also `400` (`asset.service.ts:592-606`). The app does not read the message. The toast is `error_title`.

After a completed `PUT` or `DELETE`, the app waits up to 10 seconds for a websocket event `AssetEditReadyV1` or `AssetEditReadyV2` whose `asset.id` is this asset (`edit_asset.action.dart:74-82`, `reference/immich/mobile/lib/providers/websocket.provider.dart:118-136`). A timeout is swallowed. The success toast still shows. v3.3.6 sends `AssetEditReadyV2` only, and only after `AssetEditThumbnailGeneration` finishes (`reference/immich/server/src/services/job.service.ts:132-164`). The payload is `asset` (`SyncAssetV2`, including `isEdited`) and `edit` (`SyncAssetEditV1[]`). The listener writes the asset, deletes every local edit for that id, and inserts the payload list (`reference/immich/mobile/lib/domain/services/sync_stream.service.dart:469-497`, `reference/immich/mobile/lib/providers/websocket.provider.dart:186-188`). A late event still writes. The 10 second wait does not remove that listener.

`AssetEditReadyV1` is still handled (`sync_stream.service.dart:426-459`). v3.3.6 does not emit it. On V1 a missing `edit` list is stored as no edits. On V2 a missing `edit` list throws before the write, the handler logs, and the local rows stay as they were (`sync_stream.service.dart:491-497`, `464-466`).

## Clearing

Reset puts the crop back to the full rectangle, the rotation to 0, and both mirrors off. It does not call HTTP (`editor.provider.dart:97-107`, `edit.page.dart:335-349`). The button is disabled when the screen already has no edits. Reset marks the screen dirty, so Save becomes enabled. Save then sends the empty list, which is `DELETE /api/assets/{id}/edits`.

`DELETE` requires `asset.edit.delete` and returns an empty `204` (`asset.controller.ts:260-269`). The service deletes every edit for that asset and queues the same thumbnail job (`asset.service.ts:619-628`). A missing asset is `400` and nothing is deleted. An asset that had no edits still returns `204` and still queues the job.

The local rows do not disappear at the `DELETE`. They disappear when `AssetEditReadyV2` arrives with an empty `edit` list, or when `AssetEditDeleteV1` sync lines arrive. Until then, opening the editor again shows the previous crop, rotate, and mirror.

## Showing the edited still

The timeline tile and the viewer call `getThumbnailImageProvider` and `getFullImageProvider` without an `edited` argument (`reference/immich/mobile/lib/presentation/widgets/images/thumbnail.widget.dart:50`, `reference/immich/mobile/lib/presentation/widgets/asset_viewer/asset_page.widget.dart:357-362`). The default is `true` (`reference/immich/mobile/lib/presentation/widgets/images/image_provider.dart:159-163`, `206-212`). The query is `edited=true` on `GET /api/assets/{id}/thumbnail` for `size=thumbnail` and `size=preview`, and on `GET /api/assets/{id}/original` when load-original is on (`reference/immich/mobile/lib/utils/image_url_builder.dart:5-16`, `reference/immich/mobile/lib/presentation/widgets/images/remote_image_provider.dart:109-157`).

`edited=true` does not read the asset's `isEdited` flag. When the request is remote, a still that was never edited still sends `edited=true`. The server orders `asset_file` by `isEdited` descending and takes the first row of that size (`reference/immich/server/src/repositories/asset.repository.ts:1173-1182`). An edited file wins when the row exists. Otherwise the unedited file of that size is the one returned. No row of that size is `404` (`reference/immich/server/src/services/asset-media.service.ts:266-286`). Before `AssetEditThumbnailGeneration` has written the edited file, the viewer is still asking for `edited=true` and still receives the unedited file.

`isEdited` decides whether a local file is allowed to stand in. `preferRemote` defaults to false (`reference/immich/mobile/lib/domain/models/config/image_config.dart:8`). A merged asset with `isEdited` false uses the on-device file and makes no thumbnail request (`image_provider.dart:226-229`). `isEdited` true skips that shortcut, so the viewer requests the remote file with `edited=true`. `isEdited` is a column on the remote asset, default false (`reference/immich/mobile/lib/data/db/main/table/remote/asset.dart:53`). v3.3.6 writes it from `AssetV2`, because the app asks for `AssetsV2` once the server is at least `3.0.0` (`reference/immich/mobile/lib/infrastructure/repositories/sync_api.repository.dart:48`, `server_capability.model.dart:10`, `sync_stream.repository.dart:272-296`). The websocket `AssetEditReadyV2` writes the same column from its `asset` object (`sync_stream.service.dart:496`).

The server sets `asset.isEdited` true when an edit row is inserted, and back to false when the last edit row for that asset is deleted (`reference/immich/server/src/schema/functions.ts:340-368`). That happens inside the `PUT` or `DELETE`, before the thumbnail job. The phone does not see it until the websocket payload or the next `AssetV2` sync line.

Share uses `asset.isEdited` rather than the default `true` (`reference/immich/mobile/lib/repositories/asset_media.repository.dart:207`, `223`). That is not the viewer.

## Sync lines

Against a server at least `2.6.0`, the sync request includes `AssetEditsV1` (`sync_api.repository.dart:50`). v3.3.6 takes that branch. The request name is `AssetEditsV1` (`reference/immich/server/src/enum.ts:1052`). The lines inside it are `AssetEditDeleteV1` first, then `AssetEditV1` (`reference/immich/server/src/services/sync.service.ts:421-433`).

`AssetEditV1` is `SyncAssetEditV1`: `id`, `assetId`, `action`, `parameters`, and `sequence` (`reference/immich/server/src/dtos/sync.dto.ts:180-188`). Every key is required (`immich-openapi-specs.json:30368-30404`). `id` and `assetId` are uuid strings. `action` is `crop`, `rotate`, or `mirror`. `parameters` is an object. `sequence` is an integer. None of them are nullable. The server selects `asset_edit.id`, `assetId`, `sequence`, `action`, and `parameters` (`reference/immich/server/src/database.ts:549-555`, `reference/immich/server/src/repositories/sync.repository.ts:542-547`). `updatedAt` and `updateId` are on the table and are not in that list (`reference/immich/server/src/schema/tables/asset-edit.table.ts:34-54`). `updateId` is the ack cursor, not a field the app stores.

`AssetEditDeleteV1` is `{ editId }`. The key and the uuid are required (`sync.dto.ts:190-192`, `immich-openapi-specs.json:30354-30366`). The server reads `editId` from `asset_edit_audit` for assets owned by the user (`sync.repository.ts:527-535`). Replacing the list deletes the old rows, and each deleted id is one of these lines (`asset-edit.repository.ts:16`, `reference/immich/server/src/schema/functions.ts:371-381`). There is no asset id on the delete line, and there is no "cleared" flag. A clear is one delete line per old id, and then no upsert.

The app parses `AssetEditV1` with `SyncAssetEditV1.fromJson` and `AssetEditDeleteV1` with `SyncAssetEditDeleteV1.fromJson` (`sync_api.repository.dart:156-157`). `_parseLines` does not catch a throw from `fromJson` (`sync_api.repository.dart:124-138`). `streamChanges` returns that error and stops reading the stream (`sync_api.repository.dart:117-118`). `_processBatch` acks only after the handler returns (`reference/immich/mobile/lib/domain/services/sync_stream.service.dart:181-188`). A throw from `fromJson` happens before `onData`, so that chunk is not stored and the stream stops. A throw from the handler skips the ack for that entity batch.

`isEdited` is not on `AssetEditV1`. It is required and not nullable on `SyncAssetV2` (`immich-openapi-specs.json:31119-31122`, `31179-31188`, `sync.dto.ts:110`). `upgradeDto` defaults a missing `isEdited` on `SyncAssetV1` only (`openapi_patching.dart:41`). v3.3.6 does not ask for `AssetsV1`. A missing `isEdited` on `AssetV2` fails that parse the same way.

## Stored columns

`updateAssetEditsV1` inserts `asset_edit_entity` and, on `id` conflict, updates the same companion (`sync_stream.repository.dart:418-431`). The columns are `id`, `assetId`, `action`, `parameters`, and `sequence` (`reference/immich/mobile/lib/data/db/main/table/asset/edit.dart:10-24`). The table is strict and without a row id (`reference/immich/mobile/lib/data/db/util/defaults_mixin.dart:8-9`). There is no `updatedAt`.

`action` is stored as an int enum, `rotate`, `crop`, `mirror`, `other`, in that order (`reference/immich/mobile/lib/domain/models/asset_edit.model.dart:3`, `sync_stream.repository.dart:988-993`). The wire strings map to the first three. `other` is not a wire value. `parameters` is the whole object, stored as JSON (`sync_stream.repository.dart:426`, `edit.dart:19-29`). Crop does not drop down to four named columns. Rotate does not drop down to `angle`. Mirror does not drop down to `axis`.

`assetId` references `remote_asset_entity` with cascade delete (`edit.dart:15`). An edit whose asset row is missing fails the insert. The handler rethrows (`sync_stream.repository.dart:433-435`), the batch does not commit, and the ack does not run. Deleting the asset removes its edit rows with it. `AssetEditDeleteV1` is not required for that.

`deleteAssetEditsV1` deletes by `id = editId` (`sync_stream.repository.dart:462-467`). The asset row stays. Other edits on that asset stay. An unknown id deletes nothing and does not throw.

The websocket path is not an upsert. `replaceAssetEditsV1` deletes every local edit for the asset id, then inserts the event's list (`sync_stream.repository.dart:439-454`). An empty list leaves the asset with no edit rows.

Reading a row back, `crop` is kept only when `CropParameters.fromJson` returns a value, and the same for `rotate` and `mirror` (`edit.dart:31-38`). `getAssetEdits` then applies `!` (`remote_asset.repository.dart:216`). `other` is filtered out before that. A crop object is `x`, `y`, `width`, `height`, all required integers (`immich-openapi-specs.json:21921-21954`). A rotate object is required `angle` (`immich-openapi-specs.json:27151-27163`). A mirror object is required `axis`, `horizontal` or `vertical` (`immich-openapi-specs.json:24455-24476`).

## What a missing field does

**Edit button.** A stored server version below `2.6.0` hides the button. The version starts at `0.0.0`, and a version call that returns null or throws does not replace it (`server_info.provider.dart:18-19`, `43-57`). The button does not look at edit rows.

**Opening.** A missing exif row does not open the editor and does not toast. A missing `width` or a missing `height` still opens it. The missing side is stored as 0 (`editor.provider.dart:38-40`). The stored crop is applied only when both sides are non-null (`editor.provider.dart:32-34`). With a missing side the canvas starts as the full rectangle, and rotation and mirror still apply. Save then compares the crop against those zeros, so a full rectangle adds no crop. A crop that does differ can send `width` or `height` of 0, which the server rejects (`editing.dto.ts:26-27`, `asset.service.ts:584-587`).

A stored edit whose `parameters` is not the object for its action fails while the rows are read. `fromJson` returns null when the value is not a Map, and the generator's `!` throws when a required key is missing, null, or the wrong JSON type. `getAssetEdits` then throws on a null `toDto`. The toast is the open failure, and the route is not pushed. An unknown `action` string fails earlier, at sync parse, and never lands. A local `other` row is skipped and does not by itself block the editor.

**Save.** The screen does not require a response field. It requires the call to complete. `400` from the cases above, a network failure, or a client throw stays on the editor with `error_title`. The server may already have replaced the rows before a response-parse throw. This note cannot see the generated client, so it does not decide that case. The local edit rows are unchanged either way until a websocket event or a sync line.

A websocket `AssetEditReadyV2` whose `asset` fails `SyncAssetV2.fromJson` does not write `isEdited` and does not replace the edits. One bad object in `edit` throws inside `fromJson` and has the same result. The handler catches it (`sync_stream.service.dart:503-504`). The save has already popped.

**Viewer.** The viewer does not read `asset_edit_entity`. It shows the edited still when the remote request uses `edited=true` and the edited file exists, or when `isEdited` is true and that forces the remote request. A missing `isEdited` on `AssetV2` fails the asset sync batch. The column stays at its last value, or false if the row was never written. The viewer then keeps the local file when one exists and `preferRemote` is false, and still sends `edited=true` when it does request the remote file. A missing edited `asset_file` row is the unedited file of that size, not an empty viewer, until that size has no file at all. That last case is `404`, and the photo falls back to the thumbnail ([Thumbnails and originals](thumbnails-and-originals.md)).

**Sync.** A missing `id`, `assetId`, `action`, `parameters`, or `sequence` on `AssetEditV1`, or a missing `editId` on `AssetEditDeleteV1`, fails the parse. The batch is not stored and not acked. The editor and the viewer keep the previous rows. A `parameters` object that is present but has the wrong keys for its action does land, because the sync handler stores the object as given (`sync_stream.repository.dart:426`). The failure is the next time the editor reads the row.
