# Timeline

Which HTTP calls the official mobile app makes to render the main library timeline after login. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD`).

The generated Dart client is not in the checkout (`mobile/pubspec.yaml` points at `generated/openapi`; `open-api/bin/generate-dart-sdk.sh` deletes and regenerates it). Paths below are the OpenAPI paths that script compiles, prefixed with `/api` because the app sets the client `basePath` to a URL that already ends in `/api` (`reference/immich/mobile/lib/services/api.service.dart:115-119`, `reference/immich/open-api/immich-openapi-specs.json:18391-18394`). Nest mounts the sync controller on `sync` under the global prefix `api` (`reference/immich/server/src/app.common.ts:65`, `reference/immich/server/src/controllers/sync.controller.ts:13`). The stream `POST` is hand-built. Version, ack, and ack-delete go through the generated client. A checked-in generated DTO reads a required field with `mapValueOfType<T>(json, name)!` (`reference/immich/open-api/patch/asset_edit_action_item_response_dto.dart.patch:13`), so a missing required value throws. The app treats a thrown error as a failed call.

## Sequence

The photos tab is `MainTimelineRoute`, the first child of the tab shell (`reference/immich/mobile/lib/pages/common/tab_shell.page.dart:79-80`, `reference/immich/mobile/lib/routing/router.dart:121-125`). The page builds `Timeline` (`reference/immich/mobile/lib/presentation/pages/dev/main_timeline.page.dart:40-47`). That widget watches `timelineServiceProvider`, which calls `TimelineFactory.main` (`reference/immich/mobile/lib/providers/infrastructure/timeline.provider.dart:13-16`, `reference/immich/mobile/lib/domain/services/timeline.service.dart:53`). The grid is painted from local SQLite. It does not wait for an HTTP list, and it does not call `GET /api/assets`, `GET /api/timeline/bucket`, or `GET /api/timeline/buckets`. No `getTimeBucket` call exists under `mobile/`. `assetsApi` on this tree is the later cloud-id metadata update, not a library list (`reference/immich/mobile/lib/domain/utils/migrate_cloud_ids.dart:223-242`).

**Password login.** `login()` awaits `saveAuthInfo` and ignores its boolean (`reference/immich/mobile/lib/providers/auth.provider.dart:83-86`). That stores the user from `GET /api/users/me` when the call returns one (`auth.provider.dart:141-175`). The form then awaits the gallery-permission dialog, and on Android with remote-deletion mode the manage-media dialog (`reference/immich/mobile/lib/widgets/forms/login/login_form.dart:265-272`). It then fires `handleSyncFlow` without awaiting it, connects the websocket, and replaces the route with the tab shell (`login_form.dart:273-284`). `handleSyncFlow` awaits `syncLocal(full: true)`, then awaits `syncRemote` (`login_form.dart:185-190`). Neither has to finish before the shell is shown. `shouldChangePassword && !isAdmin` opens the change-password screen instead and does not open this shell (`login_form.dart:265-266`).

**OAuth.** The form awaits `saveAuthInfo` and opens the shell only when that returns true (`login_form.dart:369-384`). It fires the same `handleSyncFlow` without awaiting it. This branch does not call `websocketProvider.connect`.

**Stored session.** Splash resolves the endpoint, then `resumeSession` (`reference/immich/mobile/lib/pages/common/splash_screen.page.dart:287-295`). If `accessToken`, `serverUrl`, and `serverEndpoint` are all in the store, it starts `saveAuthInfo` and does not wait for it (`splash_screen.page.dart:311-327`). Inside that future it connects the websocket, fires server info, and awaits `syncLocal(full: true)` and `syncRemote` together (`splash_screen.page.dart:326-333`). The splash replaces itself with the tab shell as soon as that future has been started (`splash_screen.page.dart:375-377`). A stored `currentUser` is already what the grid watches (`reference/immich/mobile/lib/providers/user.provider.dart:9-11`). `AuthGuard` allows the route when the store has an access token, then runs `POST /api/auth/validateToken` in the background (`reference/immich/mobile/lib/routing/auth_guard.dart:26-36`). A failed or false `authStatus`, or HTTP 401, replaces the shell with login (`auth_guard.dart:49-69`). That call does not fill rows.

**Later resume.** After a real pause, and only if still authenticated, the app awaits `GET /api/server/version`, connects the websocket, cancels frozen sync tasks, and awaits `syncLocal` and `syncRemote` together again (`reference/immich/mobile/lib/providers/app_life_cycle.provider.dart:76-98`, `117-143`). The grid is already up. A resume that was never paused returns before that sync (`app_life_cycle.provider.dart:76-78`).

**What fills a row.** `syncRemote` runs `SyncStreamService.sync` in an isolate (`reference/immich/mobile/lib/domain/utils/background_sync.dart:160-171`). `sync` loads the server version, may `DELETE` old ack cursors once, then `POST`s the sync stream and `POST`s an ack as each batch is written (`reference/immich/mobile/lib/domain/services/sync_stream.service.dart:59-95`, `181-188`). Asset upserts are inserted into `remote_asset_entity` (`reference/immich/mobile/lib/infrastructure/repositories/sync_stream.repository.dart:272-304`). The bucket query is a Drift watch, and a new emission reloads the asset buffer (`timeline.repository.dart:47-50`, `timeline.service.dart:112-139`). The first buffer is 1024 assets (`reference/immich/mobile/lib/constants/constants.dart:27`, `timeline.service.dart:126-128`).

The user ids are the stored user plus partners whose `in_timeline` is true (`reference/immich/mobile/lib/infrastructure/repositories/timeline.repository.dart:24-33`, `timeline.provider.dart:32-44`). Partner rows come from `PartnersV1` in the same stream (`sync_stream.repository.dart:198-209`). Partner assets are written with `updateAssetsV2` and show up when that owner id is in the list (`sync_stream.service.dart:239-240`).

The main query is `mergedAsset` / `mergedBucket` (`timeline.repository.dart:36-55`, `reference/immich/mobile/lib/data/db/main/query/merged_asset.drift:7-87`, `89-141`). The remote half keeps a row when `deleted_at` is null, `visibility` is `0`, `owner_id` is in those user ids, and `stack_id` is null or `id` equals `stack_entity.primary_asset_id` (`merged_asset.drift:36-42`, `110-117`). The column is `intEnum<AssetVisibility>`, and `timeline` is the first value, so it is stored as `0` (`reference/immich/mobile/lib/data/db/main/table/remote/asset.dart:47`, `reference/immich/mobile/lib/domain/models/asset/remote_asset.model.dart:3`). Bucket date is `local_date_time` if set, otherwise `created_at` in local time, grouped by day or month (`merged_asset.drift:96-105`). The default group is day; `auto` is treated as day (`reference/immich/mobile/lib/domain/models/config/timeline_config.dart:11`, `timeline.service.dart:47-50`). The asset list is ordered by `created_at` descending (`merged_asset.drift:86`). The local half of the union is device rows in an album marked selected (`backup_selection` `0`) and not in one marked excluded (`2`), whose checksum is not already a remote checksum for these users (`merged_asset.drift:72-85`, `reference/immich/mobile/lib/domain/models/album/local_album.model.dart:6-13`). That half is not an HTTP list. `syncLocal` is what fills it, and the shell does not wait for it.

The remote row the query builds is `id`, `localId` (a local row with the same checksum), `name`, `ownerId`, `checksum`, `type`, `createdAt`, `updatedAt`, `uploadedAt`, `thumbHash`, `width`, `height`, `isFavorite`, `durationMs`, `livePhotoVideoId`, `stackId`, `isEdited` (`timeline.repository.dart:57-76`). The tile reads `isFavorite`, `type` (video badge), `durationMs` (the video label, and an image with `durationMs > 0` is the animated badge), `livePhotoVideoId` (motion badge), `stackId` (stack badge), and `localId` (merged versus remote cloud icon) (`reference/immich/mobile/lib/presentation/widgets/images/thumbnail_tile.widget.dart:158-184`, `187-198`, `295-336`, `remote_asset.model.dart:44-64`). `thumbHash` is the placeholder when the row is remote and `localId` is null (`reference/immich/mobile/lib/presentation/widgets/images/thumbnail.widget.dart:44-47`). The thumbnail provider also reads `id`, `checksum`, `type`, and `isEdited` (`reference/immich/mobile/lib/presentation/widgets/images/image_provider.dart:206-229`). `width` and `height` change tile width only when the column count is at most 2 on a narrow window (`width < 550`) or at most 3 otherwise (`reference/immich/mobile/lib/presentation/widgets/timeline/fixed/segment.model.dart:110`, `150-151`, `reference/immich/mobile/packages/ui/lib/extensions/build_context_extensions.dart:20`). The default column count is 4, so the default grid does not read them (`timeline_config.dart:10`). The query copies `name`, `updatedAt`, and `uploadedAt` onto the row. The tile and the row layout do not read them.

`libraryId` is stored from the asset event and is not in this query (`sync_stream.repository.dart:292`). The main query does not join `remote_exif_entity`. Exif is still written, and when both asset `width` and `height` are null the exif handler copies them onto the asset (`sync_stream.repository.dart:312-366`). A one-time local `UPDATE` after the stream copies exif width and height onto every asset that has them (`reference/immich/mobile/lib/infrastructure/repositories/sync_migration.repository.dart:11-25`, `sync_stream.service.dart:150-155`). That is not an HTTP call. Album, memory, person, face, OCR, metadata, and edit rows are written by the same stream and are not columns of this query. The photos page also mounts a memory lane from the local memory table (`main_timeline.page.dart:42-44`, `reference/immich/mobile/lib/providers/infrastructure/memory.provider.dart:9-21`). That lane is not the grid and is not its own HTTP call. Trash, albums, and shared links are not how this grid is filled.

**Websocket.** The grid does not wait for it. `connect` opens a socket and returns (`reference/immich/mobile/lib/providers/websocket.provider.dart:47-70`). `on_asset_update`, `on_asset_delete`, `on_asset_trash`, `on_asset_restore`, `on_asset_hidden`, and `on_asset_stack_update` call `syncRemote(enqueue: true)` (`websocket.provider.dart:94-100`, `182-184`). `AssetUploadReadyV2` writes the payload with `updateAssetsV2` and does not open another stream (`sync_stream.service.dart:416-418`). The same is true of `AssetEditReadyV2` (`sync_stream.service.dart:496-497`).

## Calls

### `GET /api/server/version`

- When: the first line of `SyncStreamService.sync`, before any sync `POST`. A null body returns false and the stream is not opened (`sync_stream.service.dart:61-65`). Splash also fires this inside `getServerInfo` after the shell is already being shown (`splash_screen.page.dart:327`). A later resume awaits it before the next `syncRemote` (`app_life_cycle.provider.dart:90`). The grid does not wait on either call.
- Method and path: `GET /api/server/version`. Public. Operation `getServerVersion` (`immich-openapi-specs.json:13450-13453`, `reference/immich/server/src/controllers/server.controller.ts:77-86`).
- Request: no body, no query. Generated client, so the shared native client sends the session cookie and `User-Agent`. `deviceModel` and `deviceType` are on this call only after `setDeviceInfoHeader`, which runs from the login URL check and not from splash (`reference/immich/mobile/lib/services/api.service.dart:155-169`, `reference/immich/mobile/lib/services/auth.service.dart:55-58`).
- Response fields the app requires: `major`, `minor`, and `patch` (`patch_` on the DTO). Those three become the `SemVer` passed to every `supports` check. `prerelease` is not copied into that `SemVer` (`sync_stream.service.dart:67`). `supports` is `>=` the capability's minimum (`reference/immich/mobile/lib/utils/semver.dart:72-74`, `reference/immich/mobile/lib/domain/models/server_capability.model.dart:27-28`). A null DTO skips the stream. The version check against v3.3.6 is below, on the stream call.
- Source: `sync_stream.service.dart:61-67`. Server: `server.controller.ts:77-86`.

### `DELETE /api/sync/ack`

- When: inside `sync`, after the version call and before the stream, once per migration flag missing from `StoreKey.syncMigrationStatus`. A later sync that already stored the flag does not call it (`sync_stream.service.dart:69-77`, `107-148`). The flags are written to the store before the stream starts, so a stream failure does not repeat a delete that already returned (`sync_stream.service.dart:74-77`).
- Method and path: `DELETE /api/sync/ack`. Operation `deleteSyncAck` (`immich-openapi-specs.json:14948-14951`). Authenticated. The server requires a session and rejects an API key (`reference/immich/server/src/services/sync.service.ts:98-100`, `138-144`).
- Request: JSON `SyncAckDeleteDto` `{ "types": [...] }` (`reference/immich/mobile/lib/infrastructure/repositories/sync_api.repository.dart:23-24`, `reference/immich/server/src/dtos/sync.dto.ts:557-561`). On the first run against a server this app treats as v3.3.6, four deletes run, in order. `AlbumV1`, then `AssetExifV1`, `PartnerAssetExifV1`, `AlbumAssetExifCreateV1`, and `AlbumAssetExifUpdateV1`, have no version gate. The next delete, `AssetV1`, `PartnerAssetV1`, `AlbumAssetCreateV1`, and `AlbumAssetUpdateV1`, runs because v3.3.6 is past `assetPayloadChange20260128` (2.5.0). The last delete, `AssetV1` and `AssetV2`, runs because v3.3.6 is past `assetPayloadChange20260597` (2.7.6) (`sync_stream.service.dart:108-147`, `server_capability.model.dart:19-20`). Deleting `AssetV2` drops the asset cursor, so the following stream sends asset upserts from the start. Deleting `AlbumV1` does not drop `AlbumV2`. The exif delete does drop `AssetExifV1`, which this app still requests.
- Response fields the app requires: none. The future is awaited and the body is not read. The server status is 204 (`sync.controller.ts:62-71`). A throw fails `sync` before the stream.
- Source: `sync_api.repository.dart:23-24`, `sync_stream.service.dart:107-148`. Server: `sync.controller.ts:62-71`, `sync.service.ts:138-144`.

### `POST /api/sync/stream`

- When: `sync`, after the version call and the ack deletes. This is the call that returns library rows. If the body contains `SyncResetV1`, the app wipes remote tables, acks that line, and opens this `POST` a second time (`sync_stream.service.dart:80-94`, `171-173`, `296-297`, `sync_stream.repository.dart:46-76`). Password login and OAuth start it from `handleSyncFlow` without waiting for the shell. Splash and a later resume start it in parallel with local sync, also without blocking the first frame.
- Method and path: `POST /api/sync/stream`. No query. Operation `getSyncStream` (`immich-openapi-specs.json:15103-15106`). The URL is `{basePath}/sync/stream` (`sync_api.repository.dart:37`). Server route `POST sync/stream`, status 200, response `Content-Type: application/jsonlines+json` (`sync.controller.ts:20-30`).
- Request: JSON `SyncStreamDto`. The app sets `types` and does not pass `reset` (`sync_api.repository.dart:43-73`). `reset` is optional on the schema (`sync.dto.ts:537-541`). The server runs `resetSyncProgress` only when `dto.reset` is set (`sync.service.ts:166-168`). Headers on this request object are `Content-Type: application/json` and `Accept: application/jsonlines+json` (`sync_api.repository.dart:39-42`). The client is `NetworkRepository.client` unless a caller passes another (`sync_api.repository.dart:36`). That is the shared native client (`reference/immich/mobile/lib/infrastructure/repositories/network.repository.dart:21-33`, `54-59`), the same one `ApiClient` uses (`api.service.dart:51-58`). Android's interceptor sets `User-Agent` `immich-android/<version>`, saved custom headers, and `Authorization: Basic` only when the URL has userinfo, and the cookie jar adds `Cookie` (`reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/core/HttpClientManager.kt:56`, `362-373`, `464-470`). iOS sends the shared cookie store and `User-Agent` `immich-ios/<version>` plus saved headers (`reference/immich/mobile/ios/Runner/Core/URLSessionManager.swift:54-57`, `147-156`). This `POST` does not go through the generated client, so it does not add `deviceModel` or `deviceType`. The app does not set `Authorization: Bearer` (`api.service.dart:16`).
- Types for a server version `>=` v3.3.6: `AuthUsersV2`, `UsersV1`, `AssetsV2`, `AssetExifsV1`, `AssetEditsV1`, `AssetMetadataV1`, `PartnersV1`, `PartnerAssetsV2`, `PartnerAssetExifsV1`, `AlbumsV2`, `AlbumUsersV1`, `AlbumAssetsV2`, `AlbumAssetExifsV1`, `AlbumToAssetsV1`, `MemoriesV2`, `MemoryToAssetsV2`, `StacksV1`, `PartnerStacksV1`, `UserMetadataV1`, `PeopleV1`, `AssetFacesV3`, `AssetOcrV1` (`sync_api.repository.dart:45-72`, `server_capability.model.dart:10-16`, `reference/immich/server/src/enum.ts:1039-1075`). The v1 asset, album, partner-asset, memory, and face request types are the other branch of those gates. v3.3.6 does not take them. The server walks `SYNC_TYPES_ORDER` and skips a type the body did not ask for (`sync.service.ts:64-96`, `227-234`).
- There is no page query and no server `LIMIT`. One response is every selected change, then one `SyncCompleteV1` line, then the body ends (`sync.service.ts:227-238`). A cursor is the last ack the server stored for that session and entity type (`sync.service.ts:177-178`, `reference/immich/server/src/repositories/sync-checkpoint.repository.ts:14-31`). Asset upserts are `asset.updateId < nowId`, and `updateId > ack.updateId` when an ack exists, ordered by `updateId` (`reference/immich/server/src/repositories/sync.repository.ts:136-145`, `403-409`). Deletes use the same shape on `asset_audit.id` (`sync.repository.ts:116-124`, `391-396`). `nowId` is a uuid v7 of `now() - 1 millisecond` (`sync-checkpoint.repository.ts:44-49`). `updateId` is a uuid v7 of the row's clock time (`reference/immich/server/src/schema/functions.ts:3-22`). The client splits the body on newlines and hands them to the handler every 5000 lines, and again for the tail (`reference/immich/mobile/lib/constants/constants.dart:9`, `sync_api.repository.dart:96-116`). That 5000 is a parse batch. It is not a server page. Each line is JSON `type`, `data`, and `ack` (`sync_api.repository.dart:124-138`). `ack` is a string `type|updateId` or `type|updateId|extraId` (`reference/immich/server/src/utils/sync.ts:11-17`, `28-34`). An unknown `type` is skipped (`sync_api.repository.dart:132-136`). A null `type` throws on `!`. The client groups consecutive lines of one type and writes that group before reading further (`sync_stream.service.dart:158-188`).
- A reset line is `SyncResetV1` with ids `['reset']`. The server sends it and ends the body when `isPendingSyncReset` is set, or when a stored `SyncCompleteV1` ack is older than 30 days (`sync.service.ts:31-32`, `170-184`, `263-271`). The app's `reset` deletes the remote tables, including `remote_asset_entity` and `stack_entity` (`sync_stream.repository.dart:46-76`). The ack of that line is what clears the session checkpoints: `setAcks` sees `SyncResetV1` and calls `resetSyncProgress` (`sync.service.ts:120-124`, `reference/immich/server/src/repositories/session.repository.ts:139-146`). The second `POST` then has no cursors, so it is a full stream. The app does not send `reset: true` itself.
- Response fields the asset writer reads, for `AssetV2` (and the same shape for partner and album asset lines): `id`, `originalFileName`, `type`, `fileCreatedAt`, `fileModifiedAt`, `createdAt`, `duration`, `checksum`, `isFavorite`, `ownerId`, `localDateTime`, `thumbhash`, `deletedAt`, `visibility`, `livePhotoVideoId`, `stackId`, `libraryId`, `width`, `height`, `isEdited` (`sync_stream.repository.dart:276-296`). `fileCreatedAt` null leaves `created_at` unset on that write (`Value.absentIfNull`). `createdAt` on the event is stored as `uploaded_at`. `duration` is stored as `duration_ms` (`sync_stream.repository.dart:282`). The server column is the integer metadata writes in milliseconds (`reference/immich/server/src/services/metadata.service.ts:1104-1108`, `reference/immich/server/src/dtos/asset-response.dto.ts:43`). `checksum` and `thumbhash` are base64 (`sync.service.ts:34-38`). `type` is `IMAGE`, `VIDEO`, `AUDIO`, or `OTHER` (`reference/immich/server/src/enum.ts:38-43`). `visibility` is `timeline`, `hidden`, `archive`, or `locked` (`enum.ts:1211-1219`). HTTP status must be 200 or the app throws and does not parse the body (`sync_api.repository.dart:89-94`).
- Of those stored asset columns, the main grid's filter and order use `id`, `owner_id`, `checksum`, `deleted_at`, `visibility`, `created_at`, `local_date_time`, and `stack_id`, plus `stack_entity.primary_asset_id`. The tile and the default row use `id`, `local_id`, `checksum`, `type`, `thumb_hash`, `is_favorite`, `duration_ms`, `live_photo_video_id`, `stack_id`, and `is_edited`. `name`, `updated_at`, and `uploaded_at` are selected into the row and not drawn. `library_id` is stored and not selected. `width` and `height` are selected and are read only in the short-row layout described above. Exif fields the repository stores (`city`, `state`, `country`, `dateTimeOriginal`, `description`, `exposureTime`, `fNumber`, `fileSize`, `focalLength`, `latitude`, `longitude`, `iso`, `make`, `model`, `orientation`, `timeZone`, `rating`, `projectionType`, `lens`, and exif `width` / `height`) are not joined by this query (`sync_stream.repository.dart:316-338`). The exif event also has `modifyDate`, `profileDescription`, and `fps` (`sync.dto.ts:144-161`). The repository does not write those three.
- Source: `sync_api.repository.dart:27-142`, `sync_stream.service.dart:59-190`. Server: `sync.controller.ts:20-36`, `sync.service.ts:147-238`, `334-346`.

### `POST /api/sync/ack`

- When: after each consecutive same-type group is written, including the `SyncCompleteV1` line and a `SyncResetV1` line (`sync_stream.service.dart:181-188`, `289-297`). The body is one ack string, the last line of that group. A group that spans two 5000-line chunks is acked at the end of each chunk. The server keeps one row per session and entity type and replaces `ack` (`sync-checkpoint.repository.ts:22-31`). The next stream's `updateId > ack.updateId` filter is that cursor. `SyncAckV1` is a no-op write, then the same ack (`sync_stream.service.dart:286-290`).
- Method and path: `POST /api/sync/ack`. Operation `sendSyncAck` (`immich-openapi-specs.json:15051-15053`). Authenticated, session required (`sync.service.ts:113-117`).
- Request: JSON `{ "acks": ["<ack>"] }` (`sync_api.repository.dart:19-20`, `sync.dto.ts:551-555`). The schema allows at most 1000 strings. This caller sends one. Generated client, so cookie, `User-Agent`, and saved custom headers come from the native client, and `deviceModel` / `deviceType` only if the URL check already set them. `Content-Type: application/json`.
- Response fields the app requires: none. The future is awaited and the body is not read. The server status is 204 (`sync.controller.ts:49-59`). An ack whose type is `SyncResetV1` clears every checkpoint for the session and does not store that ack (`sync.service.ts:120-124`). Any other ack is upserted. A throw fails the rest of the stream. Rows already written stay. The next stream replays from the last ack that was stored.
- Source: `sync_api.repository.dart:19-20`, `sync_stream.service.dart:181-188`. Server: `sync.controller.ts:49-59`, `sync.service.ts:113-135`.

The app does not call `GET /api/sync/ack` (`getSyncAck` is only the server handler, `sync.controller.ts:38-46`). A search of `mobile/lib` finds `syncApi` used for `sendSyncAck` and `deleteSyncAck` only (`sync_api.repository.dart:19-24`).
