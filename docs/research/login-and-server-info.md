# Login and server info

Which HTTP calls the official mobile app makes to reach the timeline: discover a server, log in, keep the session, and the server checks it runs along that path. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD`).

The generated Dart client is not in the checkout (`mobile/pubspec.yaml` points at `generated/openapi`; `open-api/bin/generate-dart-sdk.sh` deletes and regenerates it). Paths below are the OpenAPI paths that script compiles, prefixed with `/api` because the app sets the client `basePath` to a URL that already ends in `/api` (`reference/immich/mobile/lib/services/api.service.dart:115-119`, `reference/immich/open-api/immich-openapi-specs.json:18391-18394`). The integration fake server receives `GET /api/server/ping` and `GET /api/server/version` (`reference/immich/mobile/integration_test/test_utils/fake_immich_server.dart:50-55`). Nest controllers use the same paths under the global prefix `api` (`reference/immich/server/src/app.common.ts:65`).

The generated client is not in the checkout (`openapi-generator` `7.25.0`, `reference/immich/open-api/openapitools.json:5`). A checked-in generated DTO reads a required field with `mapValueOfType<T>(json, name)!` (`reference/immich/open-api/patch/asset_edit_action_item_response_dto.dart.patch:13`), so a missing required value throws. Before parse, the mobile patch fills a few missing keys (`reference/immich/mobile/lib/utils/openapi_patching.dart:18-48`, applied from `reference/immich/open-api/templates/mobile/serialization/native/native_class.mustache.patch:7`) and removes the debug-only required-key asserts. A missing required field that the patch does not fill fails that DTO. The app treats a thrown error as a failed call. It does not read the HTTP status itself.

## Sequence

**No server yet.** The app has no first-user screen and never calls `POST /api/auth/admin-sign-up`. Cold start with any of `accessToken`, `serverUrl`, or `serverEndpoint` missing in the store calls logout and shows the login form (`reference/immich/mobile/lib/pages/common/splash_screen.page.dart:306-370`). Logout skips HTTP when `basePath` is empty, which is the clean install (`reference/immich/mobile/lib/repositories/auth_api.repository.dart:29-34`). The user types a URL and taps Next. That runs, in order: `GET /.well-known/immich` (failure ignored), `GET /api/server/ping` (must not throw), then `GET /api/server/version`, `GET /api/server/features`, and `GET /api/server/config`. Version, features, and config failures do not block the form. They leave the defaults: password login shown, OAuth hidden, version warning only. There is still no account call.

**Login.** Password: `POST /api/auth/login`. The form then goes to the timeline unless `shouldChangePassword` is true and `isAdmin` is false, in which case it opens the change-password screen instead (`reference/immich/mobile/lib/widgets/forms/login/login_form.dart:265-284`). OAuth, only if features said it is enabled: `POST /api/oauth/authorize`, the system browser, then `POST /api/oauth/callback`, then the timeline with no password-change branch (`reference/immich/mobile/lib/widgets/forms/login/login_form.dart:325-384`). Both success paths then call `GET /api/users/me` and `GET /api/users/me/preferences` together. A failure there is caught and does not by itself stop navigation (`reference/immich/mobile/lib/providers/auth.provider.dart:83-87`, `141-160`). `POST /api/auth/validateToken` runs in the background as the timeline route is allowed; it can send the user back to login (`reference/immich/mobile/lib/routing/router.dart:121-128`, `reference/immich/mobile/lib/routing/auth_guard.dart:21-69`).

**Stored session.** Splash calls endpoint switching first. That pings only when auto-switching is on and a local or external URL is saved; a failed ping is skipped and the stored endpoint stays (`reference/immich/mobile/lib/pages/common/splash_screen.page.dart:287-295`, `reference/immich/mobile/lib/services/auth.service.dart:141-196`). If `accessToken`, `serverUrl`, and `serverEndpoint` are all in the store, splash replaces itself with the timeline shell without waiting for the network (`reference/immich/mobile/lib/pages/common/splash_screen.page.dart:311-378`). In parallel it repeats `users/me` + preferences, connects the websocket, and fires version, features, and config. `AuthGuard` allows the route if the store has an access token, then runs `validateToken` in the background. A later resume, after a real pause and only if still authenticated, calls version again (`reference/immich/mobile/lib/providers/app_life_cycle.provider.dart:82-90`). None of version, features, or config can block the shell. `validateToken` can remove it afterwards.

**Session, no refresh call.** `ApiClient` is built with no bearer authenticator (`reference/immich/mobile/lib/services/api.service.dart:16`), so the app does not set `Authorization: Bearer`. Login and the OAuth callback set cookies; the native jar stores them and sends `Cookie` on later requests (`reference/immich/server/src/controllers/auth.controller.ts:43-49`, `reference/immich/server/src/controllers/oauth.controller.ts:82-88`, `reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/core/HttpClientManager.kt:362-373`, `reference/immich/mobile/ios/Runner/Core/URLSessionManager.swift:147-156`). Cookie names: `immich_access_token` (the session token), `immich_auth_type` (`password` or `oauth`), `immich_is_authenticated` (`true`), path `/`, `SameSite=Lax`, `Max-Age` 400 days, `Secure` when the login request was HTTPS, `HttpOnly` except `immich_is_authenticated` (`reference/immich/server/src/enum.ts:9-16`, `reference/immich/server/src/utils/response.ts:42-67`). The server accepts that cookie, or `Authorization: Bearer`, or `x-immich-user-token`, or `x-immich-session-token` (`reference/immich/server/src/services/auth.service.ts:250-269`). This app only produces the cookie. The JSON `accessToken` is also stored in the local store and copied to the home-screen widget (`reference/immich/mobile/lib/providers/auth.provider.dart:127-134`). The live path does not write that stored token back into the jar. `updateHeaders()` is called without a token (`reference/immich/mobile/lib/services/api.service.dart:51-53`). The only writer of a token into the jar is a one-time store migration (`reference/immich/mobile/lib/utils/migration.dart:123-157`). There is no refresh request. If the jar loses the cookie, the next `validateToken` is unauthorized and the app returns to login.

Headers on the calls below, from the native client: `User-Agent` `immich-android/<version>` or `immich-ios/<version>` (`HttpClientManager.kt:56`, `HttpClientManager.kt:367`; `URLSessionManager.swift:54-57`). Custom headers the user saved, if any (`api.service.dart:191-193`, restored at `HttpClientManager.kt:139-147`). `Cookie` once the jar has one. After a successful URL check in this process, generated calls also send `deviceModel` and `deviceType` (`api.service.dart:155-169`). A cold resume does not set those two again. Android adds `Authorization: Basic` only when the server URL itself contains userinfo (`HttpClientManager.kt:370-372`). JSON calls get `Content-Type: application/json` from the generated client. No call in this note sends a query string.

## Calls

### `GET /.well-known/immich`

- When: URL check, before ping. Not used on resume unless endpoint switching resolves a new URL. Failure is ignored.
- Method and path: `GET {normalized URL}/.well-known/immich`. The user URL is given `https://` if it has no scheme, trailing slashes are removed, and the host is punycode-encoded (`reference/immich/mobile/lib/widgets/forms/login/login_form.dart:93-103`, `reference/immich/mobile/lib/services/api.service.dart:98-105`, `132-136`). This path is outside `/api` (`reference/immich/server/src/constants.ts:63`, `reference/immich/server/src/controllers/app.controller.ts:10-18`). It is a raw `client.get`, not the generated client, with a 5 second timeout.
- Request: no body, no query, no `deviceModel` / `deviceType`. Native `User-Agent`, saved custom headers, and cookies still apply.
- Response fields the app requires: HTTP 200, then JSON `api.endpoint` as a string (`api.service.dart:138-145`). A relative value (`/api` on this server) is joined to the URL the user typed. Anything else, including a non-200 or a timeout, is treated as "no well-known document" and the typed URL is used as-is. A missing `api.endpoint` throws inside this parser and is also ignored.
- Source: `reference/immich/mobile/lib/services/api.service.dart:132-152`. Server: `reference/immich/server/src/controllers/app.controller.ts:11-18`.

### `GET /api/server/ping`

- When: immediately after well-known, inside URL resolution. The same ping runs for each candidate when endpoint switching resolves a local or external URL. The ping must not throw or the URL is rejected (`ApiException(503, "Server is not reachable")`, `api.service.dart:107-109`).
- Method and path: `GET /api/server/ping`. If the resolved URL does not already end in `/api`, the app appends `/api` before the ping (`api.service.dart:115-120`). Timeout 5 seconds.
- Request: no body, no query. Public. `deviceModel` and `deviceType` are set after this ping returns, so the ping itself does not send them (`auth.service.dart:55-58`).
- Response fields the app requires: none of the body. The return value is discarded (`api.service.dart:120`). Schema `ServerPingResponse` requires `res` (`immich-openapi-specs.json:27940-27949`). A body that fails that parse throws, and the URL is rejected, as do a timeout, a socket error, and any other exception (`api.service.dart:121-128`).
- Source: `reference/immich/mobile/lib/services/api.service.dart:115-129`. Server: `reference/immich/server/src/controllers/server.controller.ts:66-75`.

### `GET /api/server/version`

- When: after a URL is accepted, as the first call of `getServerInfo`, before the password form (`login_form.dart:108-109`, `server_info.provider.dart:36-38`). On a stored-session start it is fired after the timeline shell is already up (`splash_screen.page.dart:327`). On a later resume, only if the app was actually paused and the user is authenticated (`app_life_cycle.provider.dart:82-90`). Not a gate. The login form's banner uses only the major-version rule in `version_compatibility.dart`. After the shell is up, the app bar uses `versionWarningPresentProvider` (`server_info.provider.dart:106-112`, `reference/immich/mobile/lib/widgets/common/immich_sliver_app_bar.dart:107`).
- Method and path: `GET /api/server/version`. Public.
- Request: no body, no query. On the login-form path, `deviceModel` and `deviceType` are already set.
- Response fields the app requires: `major`, `minor`, `patch` (Dart name `patch_`), and `prerelease`. All four are copied into `ServerVersion` (`reference/immich/mobile/lib/models/server_info/server_version.model.dart:6-8`). `major`, `minor`, and `patch` are required non-null integers; `prerelease` is required but nullable, and null means "not a prerelease" (`reference/immich/mobile/lib/utils/semver.dart:3-9`). A null DTO or a parse error sets `versionStatus` to `error` and leaves the stored version at `0.0.0` (`server_info.provider.dart:43-57`). Comparison: server older than the app, or server older than a later websocket "latest" version, is `serverOutOfDate`; app behind by more than a patch is `clientOutOfDate`; otherwise `upToDate` (`server_info.provider.dart:61-77`). The login-form banner only complains when the app major is below the server major, or more than one major ahead (`version_compatibility.dart:7-14`). The login button stays enabled. Remote sync, after the shell is up, calls this again and skips that sync if the DTO is null (`reference/immich/mobile/lib/domain/services/sync_stream.service.dart:61-65`); that is not a pre-timeline gate.
- Source: `reference/immich/mobile/lib/services/server_info.service.dart:29-38`, `reference/immich/mobile/lib/providers/server_info.provider.dart:43-77`. Server: `reference/immich/server/src/controllers/server.controller.ts:77-86`. Schema: `immich-openapi-specs.json:13450`.

### `GET /api/server/features`

- When: second call of `getServerInfo`, still before the password form, and again in the background after a stored-session start. Also refreshed on the websocket `on_config_update` event (`reference/immich/mobile/lib/providers/websocket.provider.dart:139-141`), which is after the shell. A failed fetch does not block login. The form keeps its defaults: password login on, OAuth off (`server_info.provider.dart:20`, `85-90`).
- Method and path: `GET /api/server/features`. Public. Deprecated on the server since v3.2.0 in favor of `getPublicConfig`, but this app still calls this method (`server.controller.ts:99-111`).
- Request: no body, no query.
- Response fields the app requires: it copies `trash`, `map`, `oauth` (stored as `oauthEnabled`), `passwordLogin`, `ocr`, and `smartSearch` (`reference/immich/mobile/lib/models/server_info/server_features.model.dart:18-25`). Before the timeline, only two are read: `oauth` shows or hides the OAuth button, `passwordLogin` shows or hides the email/password form (`login_form.dart:118-119`). If both are false the form shows "login disabled" and there is no way on (`login_form.dart:528`). `trash`, `smartSearch`, and `ocr` change library, delete, and search UI later, not this gate. `map` is copied and no reader of that flag was found. `ocr` and `realtimeTranscoding` are defaulted to false when missing (`openapi_patching.dart:42`), so an older body without them still parses. Every other required boolean (`configFile`, `duplicateDetection`, `email`, `facialRecognition`, `importFaces`, `map`, `oauth`, `oauthAutoLaunch`, `passwordLogin`, `reverseGeocoding`, `search`, `sidecar`, `smartSearch`, `trash`) is force-unwrapped. Omitting one fails the DTO, the service returns null, and the form stays on the defaults above.
- Source: `reference/immich/mobile/lib/services/server_info.service.dart:41-50`, `login_form.dart:114-120`. Server: `server.controller.ts:99-111`. Schema: `immich-openapi-specs.json:13073`.

### `GET /api/server/config`

- When: third call of `getServerInfo`, same places as features, including the websocket refresh. Failure keeps the previous config (trash 30 days, empty OAuth button text, empty external domain, default map style URLs) and does not block the timeline (`server_info.provider.dart:21-27`, `93-98`).
- Method and path: `GET /api/server/config`. Public. Also deprecated since v3.2.0 in favor of `getPublicConfig`; this app still calls it (`server.controller.ts:114-126`).
- Request: no body, no query.
- Response fields the app requires: `trashDays`, `oauthButtonText`, `externalDomain`, `mapDarkStyleUrl`, `mapLightStyleUrl` (`reference/immich/mobile/lib/models/server_info/server_config.model.dart:16-22`). Before the timeline, only `oauthButtonText` is read: non-empty text labels the OAuth button, empty becomes `OAuth` (`login_form.dart:120`). The others are for trash copy, share links, and the map, after the shell. `mapLightStyleUrl`, `mapDarkStyleUrl` (default tile URLs), and `minFaces` (default `3`) are filled when null (`openapi_patching.dart:31-35`). The schema also requires `externalDomain`, `isInitialized`, `isOnboarded`, `loginPageMessage`, `maintenanceMode`, `oauthButtonText`, `publicUsers`, `trashDays`, and `userDeleteDelay`. The app does not read `isInitialized`, `isOnboarded`, `loginPageMessage`, `maintenanceMode`, `publicUsers`, `userDeleteDelay`, or `oauthAccountManagementUrl`. Omitting an unpatched required field fails the DTO and the call is ignored.
- Source: `server_info.service.dart:53-62`, `server_config.model.dart:16-22`, `login_form.dart:120`. Server: `server.controller.ts:114-126`. Schema: `immich-openapi-specs.json:13028`.

### `POST /api/auth/login`

- When: password form submit, only if `passwordLogin` was true (or features never loaded, so the default is true). This is the call that must succeed before the timeline on the password path.
- Method and path: `POST /api/auth/login`. Public. No bearer and no session cookie yet.
- Request: JSON body from `LoginCredentialDto`, fields `email` and `password`, both the raw text-field strings (`reference/immich/mobile/lib/repositories/auth_api.repository.dart:21-24`). `Content-Type: application/json`. `deviceModel` and `deviceType` are set. The server also reads `User-Agent` for the session's app version, and falls back to `deviceModel` / `deviceType` for device type and OS (`reference/immich/server/src/utils/request.ts:16-24`, `reference/immich/server/src/services/auth.service.ts:615-632`).
- Response fields the app requires: a non-null `LoginResponseDto` (`auth_api.repository.dart:22-26`, `37-46`). It copies `accessToken`, `isAdmin`, `name`, `profileImagePath`, `shouldChangePassword`, `userEmail`, and `userId`. `accessToken` is stored and is the session secret. The navigation branch uses `shouldChangePassword` and `isAdmin` only (`login_form.dart:265-284`). `name`, `profileImagePath`, `userEmail`, and `userId` are copied and then unused on this branch; a missing one still fails the mapper because those constructor arguments are required. `isOnboarded` is not read. It is defaulted to false when null (`openapi_patching.dart:39`), so a body without it still parses. The spec's success status is 201 (`immich-openapi-specs.json:5694`). Any status >= 400 throws, the form shows a generic failure toast, and the timeline is not shown (`login_form.dart:287-298`). The response also `Set-Cookie`s the three cookies above with `immich_auth_type=password` (`auth.controller.ts:43-49`). The app does not read `Logout`-style fields here. It does not check `saveAuthInfo`'s boolean; navigation uses the login DTO even if `users/me` fails (`auth.provider.dart:83-87`).
- Source: `auth_api.repository.dart:21-46`, `login_form.dart:252-284`. Server: `auth.controller.ts:30-51`. Schema: `immich-openapi-specs.json:5678`.

### `POST /api/oauth/authorize`

- When: the OAuth button, only after features reported `oauth` true. Alternate way to obtain a session. Not called on the password path.
- Method and path: `POST /api/oauth/authorize`. Public.
- Request: JSON `OAuthConfigDto` with `redirectUri` `app.immich:///oauth-callback`, `state` (32 characters from a fixed alphabet), and `codeChallenge` (base64url SHA-256 of a 42-byte verifier, `=` stripped) (`login_form.dart:301-332`, `oauth.service.dart:14-26`). `state` and `codeChallenge` are sent as present optionals. `deviceModel` and `deviceType` are set. The server also stores `immich_oauth_state` and `immich_oauth_code_verifier` cookies (`oauth.controller.ts:53-63`). The app still sends `state` and `codeVerifier` again on the callback.
- Response fields the app requires: `url`. Null, or a thrown error, aborts OAuth and stays on the form (`oauth.service.dart:20-30`, `login_form.dart:343-412`). The app opens that URL in the system browser and waits for a redirect back to `app.immich:///oauth-callback`.
- Source: `reference/immich/mobile/lib/services/oauth.service.dart:14-31`, `login_form.dart:325-357`. Server: `oauth.controller.ts:40-64`. Schema: `immich-openapi-specs.json:9143`.

### `POST /api/oauth/callback`

- When: the browser redirects back to `app.immich:///oauth-callback` during the OAuth button flow.
- Method and path: `POST /api/oauth/callback`. Public.
- Request: JSON `OAuthCallbackDto` with `url` (the full callback URL; a two-slash `app.immich:/oauth-callback` is rewritten to three slashes first), `state`, and `codeVerifier` (`oauth.service.dart:34-45`).
- Response fields the app requires: `accessToken`. It logs `userEmail` and does not read `isAdmin`, `shouldChangePassword`, or the other login fields (`login_form.dart:361-371`). A null body returns to the form with no navigation. The same `LoginResponseDto` parse rules as password login apply, including the `isOnboarded` default, because this is that DTO (`oauth.controller.ts:78`). The response replaces the OAuth cookies with the session cookies and `immich_auth_type=oauth` (`oauth.controller.ts:80-88`). Unlike password login, this path checks the boolean from `saveAuthInfo` and only then opens the timeline (`login_form.dart:369-384`). There is no change-password detour.
- Source: `oauth.service.dart:34-46`, `login_form.dart:359-384`. Server: `oauth.controller.ts:66-90`. Schema: `immich-openapi-specs.json:9223`.

### `GET /api/users/me`

- When: inside `saveAuthInfo`, after the access token is stored, on password login, OAuth success, and stored-session resume (`auth.provider.dart:127-142`). Issued in the same wait as preferences, so neither is ordered ahead of the other (`reference/immich/mobile/lib/infrastructure/repositories/user_api.repository.dart:13-14`). Not a hard gate: password login navigates from the login DTO anyway; OAuth navigates only if this refresh returns a user or a user is already in the store (`auth.provider.dart:162-177`, `login_form.dart:369-373`). HTTP 401 from this call makes `saveAuthInfo` return false (`auth.provider.dart:151-154`). Other errors are logged and, if no local user exists, OAuth stays on the form. Resume does not leave the timeline when this fails, because splash ignores the boolean (`splash_screen.page.dart:319-327`).
- Method and path: `GET /api/users/me`. Authenticated. The cookie jar sends `immich_access_token` from the login or callback `Set-Cookie`.
- Request: no body, no query.
- Response fields the app requires: the converter reads `id`, `email`, `name`, `isAdmin`, `updatedAt`, `avatarColor`, `profileChangedAt`, `profileImagePath` (only whether it is empty), `quotaSizeInBytes`, and `quotaUsageInBytes` (`reference/immich/mobile/lib/infrastructure/utils/user.converter.dart:18-32`). `saveAuthInfo` then keeps `id`, `email`, `name`, and `isAdmin` (`auth.provider.dart:168-175`). `avatarColor` must be one of `primary`, `pink`, `red`, `yellow`, `blue`, `green`, `purple`, `orange`, `gray`, `amber`; anything else becomes `primary` (`user.converter.dart:51-62`). `profileChangedAt` and `clusterGroupId` are defaulted when null (`openapi_patching.dart:38`: `profileChangedAt` to now, `clusterGroupId` to `""`). Nullable `quotaSizeInBytes` and `quotaUsageInBytes` become 0. The schema also requires `createdAt`, `deletedAt` (nullable), `license` (nullable), `oauthId`, `shouldChangePassword`, `status` (`active`, `removing`, or `deleted`), `storageLabel` (nullable), and `profileImagePath`. The converter does not read `createdAt`, `oauthId`, `shouldChangePassword`, `status`, `storageLabel`, `deletedAt`, or `license`. Omitting an unpatched required non-null field (`createdAt`, `oauthId`, `shouldChangePassword`, `status`, `id`, `email`, `name`, `isAdmin`, `avatarColor`, `profileImagePath`, `updatedAt`) fails the parse, the pair with preferences fails, and the catch path above runs. A null body (empty 2xx) makes `getMyUser` return null without throwing (`user_api.repository.dart:15-16`).
- Source: `user_api.repository.dart:13-19`, `user.converter.dart:18-32`, `auth.provider.dart:136-177`. Server: `reference/immich/server/src/controllers/user.controller.ts:55-64`. Schema: `immich-openapi-specs.json:16765`.

### `GET /api/users/me/preferences`

- When: the same wait as `users/me`. Same gate behavior, because a throw from either call fails the pair (`.wait`).
- Method and path: `GET /api/users/me/preferences`. Authenticated via the session cookie.
- Request: no body, no query.
- Response fields the app requires: `memories.enabled` only, stored as `memoryEnabled`. If the preferences DTO is null, that flag defaults to true (`user.converter.dart:25`). The generated parser still requires the whole document. The patch fills, when null: `folders`, `memories` (`enabled` true, `duration` 5), `ratings`, `people`, `tags`, `sharedLinks`, `cast`, `albums.defaultAssetOrder` `desc`, `recentlyAdded`, and `download.includeEmbeddedVideos` (`openapi_patching.dart:19-30`). It does not fill `download.archiveSize`, `emailNotifications` (`enabled`, `albumInvite`, `albumUpdate`), or `purchase` (`hideBuyButtonUntil`, `showSupportBadge`). Omitting one of those fails this DTO and therefore the user refresh. `memoryEnabled` is not read before the timeline; memories use it later (`reference/immich/mobile/lib/providers/infrastructure/memory.provider.dart:10`).
- Source: `user_api.repository.dart:13-19`, `user.converter.dart:25`, `openapi_patching.dart:19-30`. Server: `user.controller.ts:99-108`. Schema: `immich-openapi-specs.json:17258`.

### `POST /api/auth/validateToken`

- When: `AuthGuard` on the timeline shell and its tabs, after the route is already allowed (`router.dart:121-128`, `auth_guard.dart:35-36`). Runs on password login, OAuth, and stored-session start. One flight at a time. This is the session check. It does not block the first frame. It can replace the shell with login.
- Method and path: `POST /api/auth/validateToken`. Authenticated. No body (`auth_guard.dart:49`). The local gate in front of it is only "the store has `accessToken`" (`auth_guard.dart:26-33`). The request itself is authorized by the cookie, not by a header copied from that store value.
- Request: no body, no query.
- Response fields the app requires: `authStatus`. The user is sent to login and local session data is cleared when the DTO is null, or `authStatus` is not `true`, or the status is 401 (`auth_guard.dart:49-69`). Any other `ApiException`, and any network error, is logged and the timeline stays. The store token is compared before and after the call; if it changed (logout then login), the result is ignored (`auth_guard.dart:51-55`, `64-66`). The schema's only field is `authStatus` (`immich-openapi-specs.json:6073`). The server handler always returns `{ authStatus: true }` when the cookie was accepted (`auth.controller.ts:64-74`).
- Source: `reference/immich/mobile/lib/routing/auth_guard.dart:39-74`. Server: `auth.controller.ts:64-74`.

## Beyond the spec's auth list

The spec names login, logout, session, and first-user admin setup. On this path the app does not call `POST /api/auth/admin-sign-up` (`immich-openapi-specs.json:5570`, `auth.controller.ts:53-62`) and does not call any `/api/sessions` route. `sessionsApi` is used later for casting, not to reach the timeline (`reference/immich/mobile/lib/services/gcast.service.dart:144`).

If "session" means the keep-alive check, that is `POST /api/auth/validateToken` above. The auth calls on this path that are none of those four names:

- `POST /api/oauth/authorize` and `POST /api/oauth/callback`, the OAuth success path.
- `GET /api/users/me` and `GET /api/users/me/preferences`, current user after a session exists.

`GET /.well-known/immich`, ping, version, features, and config are server info, not auth.

## Not on this path

- `POST /api/auth/logout` is a settings action, and splash also calls it when the stored session is incomplete or `saveAuthInfo` throws (`auth_api.repository.dart:29-35`, `splash_screen.page.dart:362-369`). It is not required to show the timeline. Empty `basePath` skips the HTTP call. The app does not read `successful` or `redirectUri`.
- `POST /api/auth/change-password` runs only on the change-password screen, which password login opens instead of the timeline when `shouldChangePassword && !isAdmin` (`login_form.dart:265-266`, `reference/immich/mobile/lib/widgets/forms/change_password_form.dart:59-89`). Success there logs out. It is not the success path into the library.
- `GET /api/auth/status` runs only in `LockedGuard`, on the locked folder, and reads `pinCode` and `isElevated` (`reference/immich/mobile/lib/routing/locked_guard.dart:24-40`, `router.dart:168`). Not before the timeline.
- `POST /api/auth/session/unlock` with `{ "pinCode" }`, `POST /api/auth/pin-code`, and `POST /api/auth/session/lock` are PIN setup and the locked folder (`auth_api.repository.dart:49-63`, `locked_guard.dart:58`). Not before the timeline.
- `GET /api/server/storage` is backup server info (`reference/immich/mobile/lib/providers/backup/backup_server.provider.dart:18`), not this path.
- OAuth link, unlink, and backchannel logout are not called from the login or splash path (`oauth.service.dart` only calls `startOAuth` and `finishOAuth`).
