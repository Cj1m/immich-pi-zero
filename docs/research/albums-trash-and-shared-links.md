# Albums, trash, and shared links

Which HTTP calls the official mobile app makes to create, list, and update albums, add and remove assets, trash and restore assets, permanently delete them, and create, list, update, delete, and open shared links. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD`).

The generated Dart client is not in the checkout (`mobile/pubspec.yaml` points at `generated/openapi`; `open-api/bin/generate-dart-sdk.sh` deletes and regenerates it, with `useOptional=true`). Paths below are the OpenAPI paths that script compiles, prefixed with `/api` because the app sets the client `basePath` to a URL that already ends in `/api` (`reference/immich/mobile/lib/services/api.service.dart:115-119`, `reference/immich/open-api/immich-openapi-specs.json:18391-18394`). Nest mounts `albums`, `trash`, `shared-links`, and `assets` under the global prefix `api` (`reference/immich/server/src/app.common.ts:65`, `reference/immich/server/src/controllers/album.controller.ts:26`, `reference/immich/server/src/controllers/trash.controller.ts:13`, `reference/immich/server/src/controllers/shared-link.controller.ts:51`, `reference/immich/server/src/enum.ts:647`). An absent `Optional` is not a JSON field. `Optional.present(null)` is a JSON null. A checked-in generated DTO reads a required field with `mapValueOfType<T>(json, name)!` (`reference/immich/open-api/patch/asset_edit_action_item_response_dto.dart.patch:13`), so a missing required value throws. The app treats a thrown error as a failed call. Every call in this note goes through that generated client, so the shared native client sends the session cookie and `User-Agent`. The app does not set `Authorization: Bearer` (`api.service.dart:16`).

## Sequence

**Album list.** The albums tab is `AlbumsRoute`, the third child of the tab shell (`reference/immich/mobile/lib/pages/common/tab_shell.page.dart:80`, `reference/immich/mobile/lib/routing/router.dart:128`). Selecting that tab calls `RemoteAlbumNotifier.refresh` (`tab_shell.page.dart:127-128`). Pull-to-refresh does the same (`reference/immich/mobile/lib/presentation/pages/album.page.dart:23-25`). `refresh` is `RemoteAlbumRepository.getAll` (`reference/immich/mobile/lib/providers/infrastructure/remote_album.provider.dart:43-56`, `reference/immich/mobile/lib/domain/services/remote_album.service.dart:58-59`). That is a Drift join of `remote_album_entity`, its non-trashed assets (`deleted_at` null), and the owner User (`reference/immich/mobile/lib/infrastructure/repositories/remote_album.repository.dart:25-84`). It is not `GET /api/albums`. No `getAllAlbums` call exists under `mobile/lib`. The rows were written by `POST /api/sync/stream`, which this app requests as `AlbumsV2`, `AlbumUsersV1`, `AlbumAssetsV2`, `AlbumAssetExifsV1`, and `AlbumToAssetsV1` (`reference/immich/mobile/lib/infrastructure/repositories/sync_api.repository.dart:55-59`). That stream is already inventoried. This screen does not open it.

**Open one album.** A tap pushes `RemoteAlbumRoute` with the `RemoteAlbum` already in memory (`album.page.dart:54-57`). A deep link does the same only when `RemoteAlbumService.get` finds that id in SQLite. A miss opens nothing (`reference/immich/mobile/lib/services/deep_link.service.dart:125-132`). The grid is `TimelineFactory.remoteAlbum`: local album assets whose `deleted_at` is null, ordered by the album row's `order` (`reference/immich/mobile/lib/presentation/pages/remote_album.page.dart:196-201`, `reference/immich/mobile/lib/infrastructure/repositories/timeline.repository.dart:167-172`, `184-218`, `224-262`). It does not call `GET /api/albums/{id}`. Shared users and the current User's role are the same local tables (`remote_album.repository.dart:238-273`). The comments screen is a later route and uses `GET /api/activities` (`reference/immich/mobile/lib/data/server/activity.dart:17-18`, `reference/immich/server/src/controllers/activity.controller.ts:19-32`). It is not an album read and is not inventoried here.

**Create.** The albums-tab add button opens `CreateAlbumRoute` (`album.page.dart:47-49`). Save calls `createAlbumWithAssets` with the trimmed title, the trimmed description (possibly empty), and the selected assets (`reference/immich/mobile/lib/presentation/pages/create_album.page.dart:168-185`). Assets already on the server go on the create body. Local-only assets are uploaded after the album exists, then linked one by one. That upload is `POST /api/assets`, already inventoried. The link is `PUT /api/albums/{id}/assets`. "Add to album" can also create: the header dialog sends the title and the selection, and does not set a description (`reference/immich/mobile/lib/presentation/widgets/album/album_selector.widget.dart:742-751`). The viewer creates with the title and that asset's remote id, and does not set a description (`album_selector.widget.dart:798-813`). With backup album sync on, leaving album selection, or turning the switch on, creates a remote album for a device album that has no local name match: `albumName` is the device album name, `assetIds` is `[]`, description is not set (`reference/immich/mobile/lib/pages/backup/backup_album_selection.page.dart:61-70`, `reference/immich/mobile/lib/widgets/settings/backup_settings/backup_settings.dart:75-108`, `reference/immich/mobile/lib/domain/services/sync_linked_album.service.dart:105-129`). The name match is SQLite, not `GET /api/albums`.

**Update.** Rename and description are one save. The dialog always sends both (`remote_album.page.dart:275-286`). Order is a separate tap and sends only `order` (`remote_album.page.dart:105-108`, `remote_album.provider.dart:173-178`). Cover is a one-asset action and sends only `albumThumbnailAssetId` (`reference/immich/mobile/lib/presentation/actions/set_album_cover.action.dart:35-42`). Comments-and-likes on the options page sends only `isActivityEnabled` (`reference/immich/mobile/lib/presentation/pages/album_options.page.dart:220-224`). Those are all `PATCH /api/albums/{id}`. Edit, cover, and add-photos are shown to the owner, and to an editor when the stored server version supports `albumEditorUpdate` (minimum 2.6.2) (`remote_album.page.dart:191-224`, `reference/immich/mobile/lib/domain/models/server_capability.model.dart:7`). The role is the local album-user row.

**Add and remove assets.** Adding a selection splits remote ids from local-only assets (`remote_album.service.dart:36-51`, `188-208`). Remote ids are one `PUT /api/albums/{id}/assets`. Each local file is uploaded, then one `PUT` with that new id (`remote_album.service.dart:270-284`). Linked-album sync, after login, splash, a manual backup sync, and an upload-ready websocket batch, sends the same `PUT` for uploaded assets not already in the linked album (`reference/immich/mobile/lib/widgets/forms/login/login_form.dart:194-196`, `reference/immich/mobile/lib/pages/common/splash_screen.page.dart:349-350`, `backup_settings.dart:53-61`, `reference/immich/mobile/lib/providers/websocket.provider.dart:195-221`, `sync_linked_album.service.dart:40-67`). Remove is `DELETE /api/albums/{id}/assets` for the selected remote ids (`reference/immich/mobile/lib/presentation/actions/remove_from_album.action.dart:35-41`). The app does not call `PUT /api/albums/assets` (the multi-album add).

**Album users, then delete.** Invite sends `PUT /api/albums/{id}/users` with user ids and no role (`remote_album.page.dart:73-85`, `album_options.page.dart:72-84`). Remove, and leave, are `DELETE /api/albums/{id}/user/{userId}` with that User's id. Leave does not send `"me"` (`album_options.page.dart:48-63`, `remote_album.provider.dart:293-297`). No `updateAlbumUser` call exists under `mobile/lib`. The owner can delete the album. That is `DELETE /api/albums/{id}`, then the local album row is dropped (`remote_album.page.dart:111-143`). It does not trash the assets.

**Trash.** The library button is shown only when stored server features say `trash` (`reference/immich/mobile/lib/presentation/pages/library.page.dart:48-84`). That flag is `GET /api/server/features` (`reference/immich/mobile/lib/services/server_info.service.dart:41-44`, `immich-openapi-specs.json:13073-13077`), not a trash call. The trash page builds `TimelineFactory.trash`: local assets whose `deleted_at` is not null and whose owner is the current User (`reference/immich/mobile/lib/presentation/pages/trash.page.dart:24-32`, `timeline.repository.dart:331-336`). `isTrashed` is `deletedAt != null` (`reference/immich/mobile/lib/domain/models/asset/remote_asset.model.dart:72`). There is no trash list route. The day count on the page is stored `trashDays` from server config, not a trash call (`trash.page.dart:46-52`, `reference/immich/mobile/lib/models/server_info/server_config.model.dart:9-17`).

**Trash one, trash many, restore, permanent delete.** The delete action sends only assets owned by the logged-in User (`reference/immich/mobile/lib/presentation/actions/delete.action.dart:27-44`). One asset and many assets are the same `DELETE /api/assets`. `force` is false when trash is enabled and at least one selected owned asset is neither trashed nor locked. Otherwise `force` is true: trash is off, or every selected owned asset is already trashed or locked (`delete.action.dart:40-43`, `116-157`). The trash page's delete button is that permanent path. Restore of the selection, and the undo on a trash toast, are `POST /api/trash/restore/assets` (`reference/immich/mobile/lib/presentation/actions/restore.action.dart:28-41`, `delete.action.dart:84-86`). Empty trash and restore-all are the kebab menu: `POST /api/trash/empty` and `POST /api/trash/restore`, with no ids (`trash.page.dart:111-136`). An empty id list does not call the per-asset routes (`reference/immich/mobile/lib/domain/services/asset.service.dart:91-95`, `153-156`, `162-165`). Removing a device copy is not one of these calls.

**Shared links.** They are not in the sync type list (`sync_api.repository.dart:45-72`). The library button opens `SharedLinkRoute`, which calls `GET /api/shared-links` on first build and again when the page is created (`reference/immich/mobile/lib/pages/library/shared_link/shared_link.page.dart:19-28`, `reference/immich/mobile/lib/providers/shared_link.provider.dart:10-16`). A failed list is drawn as no links (`shared_link.page.dart:73-75`). A tap opens the edit page with that already-fetched object. It does not call `GET /api/shared-links/{id}` (`reference/immich/mobile/lib/widgets/shared_link/shared_link_item.dart:117`, `190`). Create is the album kebab (`SharedLinkEditRoute` with `albumId`) or the asset share action (with remote ids) (`remote_album.page.dart:224`, `reference/immich/mobile/lib/presentation/actions/share_link.action.dart:11-30`). Save is `POST /api/shared-links`. Edit save is `PATCH /api/shared-links/{id}`. Delete is `DELETE /api/shared-links/{id}` (`reference/immich/mobile/lib/pages/library/shared_link/shared_link_edit.page.dart:325-337`, `407-434`, `shared_link_item.dart:183`). The page does not add or remove assets on an existing link.

**Open a shared link.** The app has no public viewer. A search of `mobile/` finds `getMySharedLink`, `sharedLinkLogin`, `getSharedLinkById`, `addSharedLinkAssets`, and `removeSharedLinkAssets` nowhere. The only `share/` or `s/` string is the URL the app copies or hands to the system share sheet: `{externalDomain or stored server URL}/s/{slug}` when slug is non-empty, otherwise `{base}/share/{key}` (`reference/immich/mobile/lib/utils/url_helper.dart:46-54`, `shared_link_edit.page.dart:344-354`, `shared_link_item.dart:73-76`). After create, the page awaits `GET /api/server/config` so `externalDomain` is fresh (`shared_link_edit.page.dart:344-350`, `server_info.service.dart:53-55`, `immich-openapi-specs.json:13028-13032`). That is not a shared-link call. The deep-link handler accepts `album`, `asset`, `memory`, `people`, and `activity`. It does not accept a share URL (`deep_link.service.dart:49-56`, `59-83`). The list thumbnail is `GET /api/assets/{id}/thumbnail?size=thumbnail&edited=true` via `getThumbnailUrlForRemoteId` (`shared_link_item.dart:70`, `reference/immich/mobile/lib/utils/image_url_builder.dart:9-16`). That is the same thumbnail route as the library. It is not a shared-link route.

## Calls

### `POST /api/albums`

- When: the create-album page, the add-to-album "create" button, the viewer "create" button, and linked-album sync when a selected device album has no local remote album of the same name. Local assets are not on this body. They are uploaded, then added with `PUT /api/albums/{id}/assets`.
- Method and path: `POST /api/albums`. No query. Operation `createAlbum` (`immich-openapi-specs.json:2262-2264`). Authenticated. Session cookie.
- Request: JSON `CreateAlbumDto`. The app always sets `albumName`. It always sets `assetIds`, including `[]` when there are no remote ids yet (`reference/immich/mobile/lib/repositories/album_api_repository.dart:23-31`). `assetIds` is optional on the schema (`immich-openapi-specs.json:21815-21823`, `21841-21843`). `description` is set only when the caller passes a non-null string. The create-album page always passes the trimmed field, and an empty string is sent as `null` (`create_album.page.dart:179-184`, `album_api_repository.dart:26-28`). The other three callers pass null, so `description` is omitted. The app never sets `albumUsers`. The server then stores the owner as the only album User, and the thumbnail as the first allowed asset id or null (`reference/immich/server/src/services/album.service.ts:121-129`).
- Response fields the app requires: `checkNull` throws if the body is null (`reference/immich/mobile/lib/repositories/api.repository.dart:4-9`). The mapper reads `id`, `albumName`, `description`, `createdAt`, `updatedAt`, `albumThumbnailAssetId`, `isActivityEnabled`, `order`, `assetCount`, and `albumUsers.length` (`album_api_repository.dart:127-142`). `order` missing is stored as `desc`, not `asc`. Owner id and owner name are the User argument, not a response field. `isShared` is `albumUsers.length > 2`. The app does not read `shared`, `hasSharedLink`, `startDate`, `endDate`, `lastModifiedAssetTimestamp`, or `contributorCounts`. Those first two are required on `AlbumResponseDto`, so a missing value throws before the mapper (`immich-openapi-specs.json:19842-19853`). `albumUsers` is required. Each item requires `role` and `user`, and `user` requires `avatarColor`, `email`, `id`, `name`, `profileChangedAt`, and `profileImagePath` (`immich-openapi-specs.json:19922-19935`, `33587-33594`). The app only uses the array length, but a missing one of those throws. Server status is 201 (`album.controller.ts:40-48`). The local insert runs only after this returns (`remote_album.service.dart:124-130`). It writes the junction rows from the ids the app sent, not from the response (`remote_album.repository.dart:162-193`).
- Source: `album_api_repository.dart:16-35`, `127-142`. Server: `album.controller.ts:40-48`, `album.service.ts:101-137`, `reference/immich/server/src/dtos/album.dto.ts:34-56`.

### `PATCH /api/albums/{id}`

- When: rename and description together, from the album dialog. Order, from the kebab toggle. Cover, from the one-asset action. Activity, from the options switch. Each of those is its own request. A field that caller does not pass is not in that body.
- Method and path: `PATCH /api/albums/{id}`. No query. Operation `updateAlbumInfo` (`immich-openapi-specs.json:2559-2561`). Authenticated. Session cookie.
- Request: JSON `UpdateAlbumDto`. Every property is optional (`immich-openapi-specs.json:32594-32630`, `album.dto.ts:72-95`). Rename sends `albumName` (the trimmed title; the form rejects an empty title) and `description` (the trimmed text, or `null` when the field is empty) (`remote_album.page.dart:275-286`, `album_api_repository.dart:86-99`). It does not send cover, activity, or order. The order toggle sends only `order`, `asc` or `desc` (`album_api_repository.dart:81-84`, `immich-openapi-specs.json:21170-21177`). Cover sends only `albumThumbnailAssetId`. Activity sends only `isActivityEnabled`. The server writes the fields it was given and returns the album (`album.service.ts:140-164`, `reference/immich/server/src/repositories/album.repository.ts:361-369`).
- Response fields the app requires: the same `AlbumResponseDto` read as create, including the required fields the mapper does not use. `checkNull` throws on a null body. Activity uses a second method that reads only `isActivityEnabled` and still parses the whole DTO (`album_api_repository.dart:119-123`). Server status is 200 (`album.controller.ts:73-86`). The local album row is replaced from that mapped object (`remote_album.service.dart:144-155`).
- Source: `album_api_repository.dart:72-124`. Callers: `remote_album.page.dart:275-286`, `remote_album.provider.dart:173-178`, `set_album_cover.action.dart:42`, `album_options.page.dart:220-224`. Server: `album.controller.ts:73-86`, `album.service.ts:140-164`.

### `DELETE /api/albums/{id}`

- When: the owner confirms delete on the album page (`remote_album.page.dart:111-143`).
- Method and path: `DELETE /api/albums/{id}`. No query, no body. Operation `deleteAlbum` (`immich-openapi-specs.json:2432-2434`). Authenticated. Session cookie.
- Request: the album id in the path. The app does not send asset ids.
- Response fields the app requires: none. The future is awaited and the body is not read (`album_api_repository.dart:106-107`). Server status is 204 (`album.controller.ts:89-99`). The repository deletes the album row (`album.repository.ts:372-374`). A throw skips the local delete (`remote_album.service.dart:287-290`). This does not set `deletedAt` on the assets.
- Source: `album_api_repository.dart:106-107`, `remote_album.service.dart:287-290`. Server: `album.controller.ts:89-99`, `album.repository.ts:372-374`.

### `PUT /api/albums/{id}/assets`

- When: adding remote assets to an album, linking one asset that just uploaded, and linked-album sync. One call per batch of remote ids, or one call per freshly uploaded id.
- Method and path: `PUT /api/albums/{id}/assets`. No query. Operation `addAssetsToAlbum` (`immich-openapi-specs.json:2702-2704`). Authenticated. Session cookie. The upload path can pass an abort future (`album_api_repository.dart:51-57`).
- Request: JSON `BulkIdsDto` `{ "ids": ["<asset id>", ...] }` (`album_api_repository.dart:56-57`). `ids` is the only field (`immich-openapi-specs.json:21593-21608`). The app does not send a key or a slug.
- Response fields the app requires: a non-null array. Each item requires `id` and `success` (`immich-openapi-specs.json:21587-21590`). `success` true is added locally. `success` false with `error` `duplicate` is not a failure and is not inserted again. Any other `error`, or a missing `error`, is a failure and is not inserted (`album_api_repository.dart:59-66`). `error` values the schema allows are `duplicate`, `no_permission`, `not_found`, `unknown`, and `validation` (`reference/immich/server/src/dtos/asset-ids.response.dto.ts:25-31`). The app does not read `errorMessage`. Server status is 200 (`album.controller.ts:113-125`). A null body throws in `checkNull` and nothing is inserted.
- Source: `album_api_repository.dart:51-69`, `remote_album.service.dart:176-181`, `270-284`. Server: `album.controller.ts:113-125`, `album.service.ts:172-199`.

### `DELETE /api/albums/{id}/assets`

- When: "Remove from album" on a selection of remote assets in that album (`remove_from_album.action.dart:35-41`).
- Method and path: `DELETE /api/albums/{id}/assets`. No query. Operation `removeAssetFromAlbum` (`immich-openapi-specs.json:2630-2632`). Authenticated. Session cookie.
- Request: JSON `{ "ids": ["<asset id>", ...] }` (`album_api_repository.dart:37-38`).
- Response fields the app requires: a non-null array of `BulkIdResponseDto`. `success` true is removed locally. `success` false is not removed. `duplicate` is not special on this call (`album_api_repository.dart:41-47`). `id` and `success` are required. Server status is 200 (`album.controller.ts:139-151`). A null body throws and the local junction is left as it was (`remote_album.service.dart:343-346`).
- Source: `album_api_repository.dart:37-48`, `remote_album.service.dart:343-346`. Server: `album.controller.ts:139-151`.

### `PUT /api/albums/{id}/users`

- When: the owner invites people, from the album page or the options page (`remote_album.page.dart:73-85`, `album_options.page.dart:72-84`).
- Method and path: `PUT /api/albums/{id}/users`. No query. Operation `addUsersToAlbum` (`immich-openapi-specs.json:2996-2999`). Authenticated. Session cookie.
- Request: JSON `{ "albumUsers": [ { "userId": "<id>" }, ... ] }` (`album_api_repository.dart:110-112`). `albumUsers` is required and must be non-empty (`immich-openapi-specs.json:18509-18522`). The app does not set `role`. The schema default is `editor` (`immich-openapi-specs.json:19885-19901`). The local insert writes `editor` without reading the response role (`remote_album.repository.dart:338-349`).
- Response fields the app requires: a non-null `AlbumResponseDto`, because `checkNull` parses it and then discards it (`album_api_repository.dart:110-112`). The app reads no field. A missing required field on that DTO, including each `albumUsers[].user`, still throws. Server status is 200 (`album.controller.ts:154-166`).
- Source: `album_api_repository.dart:110-112`, `remote_album.service.dart:293-296`. Server: `album.controller.ts:154-166`.

### `DELETE /api/albums/{id}/user/{userId}`

- When: the owner removes someone, or a member leaves. Both pass that User's id (`album_options.page.dart:48-63`). The app does not send `me`.
- Method and path: `DELETE /api/albums/{id}/user/{userId}`. No query, no body. Operation `removeUserFromAlbum` (`immich-openapi-specs.json:2846-2849`). Authenticated. Session cookie.
- Request: album id and user id in the path (`album_api_repository.dart:115-116`).
- Response fields the app requires: none. The body is not read. There is no `checkNull`. Server status is 204 (`album.controller.ts:185-194`). A throw skips the local user delete (`remote_album.service.dart:299-302`). Leave then drops the album from the in-memory list (`remote_album.provider.dart:293-297`).
- Source: `album_api_repository.dart:115-116`, `remote_album.service.dart:299-302`. Server: `album.controller.ts:185-194`.

### `DELETE /api/assets`

- When: trash one asset, trash many, or permanently delete the owned selection. The same call. `force` false is trash. `force` true is permanent delete. The trash screen's delete button is `force` true, because those assets are already trashed (`delete.action.dart:40-43`, `136-157`). Partner assets are not in `ids`.
- Method and path: `DELETE /api/assets`. No query. Operation `deleteAssets` (`immich-openapi-specs.json:3728-3731`). Authenticated. Session cookie.
- Request: JSON `AssetBulkDeleteDto` `{ "ids": ["<asset id>", ...], "force": false }` or `"force": true` (`reference/immich/mobile/lib/repositories/asset_api.repository.dart:27-28`). The app always sets `force`. It is optional on the schema (`immich-openapi-specs.json:20151-20169`). `ids` is required. An empty list returns before this call (`asset.service.dart:153-156`, `162-165`).
- Response fields the app requires: none. The body is not read. Server status is 204 (`reference/immich/server/src/controllers/asset.controller.ts:80-89`). The server sets `deletedAt` and `status` `trashed` when `force` is false, and `deletedAt` and `status` `deleted` when `force` is true (`reference/immich/server/src/services/asset.service.ts:384-395`). `status` `deleted` is what the trash job later removes from disk (`reference/immich/server/src/services/trash.service.ts:43-55`). The app does not read `status`. After `force` false it sets the local `deletedAt` to now (`reference/immich/mobile/lib/infrastructure/repositories/remote_asset.repository.dart:104-113`). After `force` true it deletes the local asset rows (`remote_asset.repository.dart:138-143`). A throw does neither. Trashed rows leave the album grid because that query requires `deleted_at` null (`timeline.repository.dart:205`, `254`). They show on the trash grid.
- Source: `asset_api.repository.dart:27-28`, `asset.service.dart:153-168`, `delete.action.dart:40-43`, `116-157`. Server: `asset.controller.ts:80-89`, `asset.service.ts:384-395`.

### `POST /api/trash/restore/assets`

- When: restore of the selected trashed assets, and the undo button on a trash toast (`restore.action.dart:28-41`, `delete.action.dart:84-86`). One id and many ids are the same call. Undo of a restore calls `DELETE /api/assets` with `force` false (`restore.action.dart:41`).
- Method and path: `POST /api/trash/restore/assets`. No query. Operation `restoreAssets` (`immich-openapi-specs.json:16652-16655`). Authenticated. Session cookie.
- Request: JSON `{ "ids": ["<asset id>", ...] }` (`asset_api.repository.dart:31-32`). No other field. An empty list returns before the call (`asset.service.dart:91-94`).
- Response fields the app requires: the app does not read the body (`asset_api.repository.dart:31-32`). The server status is 200 and the body is `TrashResponseDto` `{ "count": <int> }` (`trash.controller.ts:40-49`, `immich-openapi-specs.json:32580-32591`). `count` is required, so a body that is present and missing `count` throws before the local restore. The server clears `deletedAt` and sets `status` `active` for ids that are trashed (`reference/immich/server/src/repositories/trash.repository.ts:39-50`). The app then sets local `deletedAt` to null (`asset.service.dart:96-97`, `remote_asset.repository.dart:116-125`). It does not use `count`.
