# Faces, people, and search

Which HTTP calls the official mobile app makes to show people, the faces it has assigned to an asset, and search results the server stored after machine learning. OCR is included because the viewer draws recognized text and the search screen can query it. Read from `reference/immich` at tag `v3.3.6`, commit `587f549f46f1cd1822a06e16dcccecef04ea4565` (`git describe --tags --exact-match HEAD`).

The generated Dart client is not in the checkout (`mobile/pubspec.yaml` points at `generated/openapi`; `open-api/bin/generate-dart-sdk.sh` deletes and regenerates it, with `useOptional=true`). Paths below are the OpenAPI paths that script compiles, prefixed with `/api` because the app sets the client `basePath` to a URL that already ends in `/api` (`reference/immich/mobile/lib/services/api.service.dart:115-119`, `reference/immich/open-api/immich-openapi-specs.json:18391-18394`). Nest mounts `people`, `search`, and `faces` under the global prefix `api` (`reference/immich/server/src/app.common.ts:65`, `reference/immich/server/src/controllers/person.controller.ts:46`, `reference/immich/server/src/controllers/search.controller.ts:26`, `reference/immich/server/src/controllers/face.controller.ts:18`). The app passes `Optional.absent()` for a field it does not set and `Optional.present` for a field it does. A checked-in generated DTO reads a required field with `mapValueOfType<T>(json, name)!` (`reference/immich/open-api/patch/asset_edit_action_item_response_dto.dart.patch:13`), so a missing required value throws. A required field that the schema marks nullable can be JSON null. Before `fromJson`, `upgradeDto` fills a null `PersonResponseDto.otherPeople`, `sharedBy`, and `sharedWith` with `[]`, and a null `SearchAssetResponseDto.nextCursor` with null (`reference/immich/mobile/lib/utils/openapi_patching.dart:43-46`, `51-77`). The app treats a thrown error as a failed call. JSON calls in this note go through the generated client, so the shared native client sends the session cookie and `User-Agent`. The app does not set `Authorization: Bearer` (`api.service.dart:16`).

## Sequence

**People list.** The library tab is `LibraryRoute`, the fourth child of the tab shell (`reference/immich/mobile/lib/pages/common/tab_shell.page.dart:80`, `reference/immich/mobile/lib/routing/router.dart:127`). The people card watches `Store.people.all()` and draws up to four face thumbnails (`reference/immich/mobile/lib/presentation/pages/library.page.dart:139`, `155`, `188-193`). A tap pushes `PeopleCollectionRoute` (`library.page.dart:164`, `router.dart:183`). That page watches the same provider and filters the list in memory by name (`reference/immich/mobile/lib/presentation/pages/people_collection.page.dart:37`, `69-78`). It does not call `GET /api/people` or `GET /api/search/person`. A search of `mobile/` finds `getAllPeople` and `searchPerson` nowhere.

`all()` is a Drift watch. The minimum face count is the synced user preference `people.minimumFaces`, or `3` when that preference has not arrived (`reference/immich/mobile/lib/data/store/person.dart:42-48`, `reference/immich/mobile/lib/domain/models/user_metadata.model.dart:38`, `54`). The query keeps a person who is not hidden, has at least one visible face with `deleted_at` null, and that face's asset is not trashed and has timeline visibility (`reference/immich/mobile/lib/data/db/main/dao/person.dart:43-59`). A named person is kept even under the minimum. An unnamed person needs `minFaces` faces (`person.dart:60-64`). Order is named people first, then face count descending (`person.dart:61-64`). The row the UI reads is `id`, `name`, `updatedAt`, and `birthDate` (`person.dart:85-86`, `reference/immich/mobile/lib/domain/models/person.model.dart:8`). `isHidden` is only a filter. `createdAt`, `ownerId`, `faceAssetId`, `isFavorite`, and `color` are stored and not drawn (`reference/immich/mobile/lib/data/db/main/table/people/person.dart:12-28`).

Those rows were written by `POST /api/sync/stream`. On a server this app treats as v3.3.6 the body asks for `PeopleV1`, `AssetFacesV3`, and `AssetOcrV1` (`reference/immich/mobile/lib/infrastructure/repositories/sync_api.repository.dart:65-71`, `reference/immich/mobile/lib/domain/models/server_capability.model.dart:13-14`, `reference/immich/server/src/enum.ts:1054`, `1069-1074`). v3.3.6 is past `syncAssetFacesV3` (3.3.0) and `syncAssetOcrV1` (3.0.0), so the v1 and v2 face request types are not sent. That stream is already inventoried. These screens do not open it. `PersonV1` is upserted with `id`, `createdAt`, `updatedAt`, `ownerId`, `name`, `faceAssetId`, `isFavorite`, `isHidden`, `color`, and `birthDate` (`reference/immich/mobile/lib/infrastructure/repositories/sync_stream.repository.dart:774-794`, `reference/immich/mobile/lib/domain/services/sync_stream.service.dart:322-323`). `PersonDeleteV1` deletes the person row (`sync_stream.repository.dart:803-807`).

**Person page.** A tap, or a `/people/{id}` deep link that finds the id in SQLite, pushes `PersonRoute` with the `Person` already in memory (`people_collection.page.dart:94-95`, `reference/immich/mobile/lib/services/deep_link.service.dart:65`, `78-80`, `145-152`). A deep-link miss opens nothing. The page does not call `GET /api/people/{id}`. It does not watch the person row again. The app bar shows the object it was given: name, birthday, age, and the local timeline's asset count (`reference/immich/mobile/lib/presentation/pages/person.page.dart:26-31`, `76-98`, `reference/immich/mobile/lib/widgets/common/person_sliver_app_bar.dart:115-118`, `230-231`, `248-293`, `reference/immich/mobile/lib/presentation/widgets/sliver_app_bar/item_count_text.widget.dart:40-42`). There is no `getPersonStatistics` call under `mobile/`.

The grid is `TimelineFactory.person` (`person.page.dart:79-88`, `reference/immich/mobile/lib/domain/services/timeline.service.dart:77-78`). The user ids are `timelineUsersProvider`, the same stored user plus partners whose `in_timeline` is true (`person.page.dart:85`, `reference/immich/mobile/lib/providers/infrastructure/timeline.provider.dart:32-44`). The filter is local: a visible face for that person with `deleted_at` null, the asset not trashed, timeline visibility, and either an owner in those user ids or any album-asset row (`reference/immich/mobile/lib/infrastructure/repositories/timeline.repository.dart:433-445`, `480-492`). It does not call `GET /api/people/{id}/statistics` or a search route. The option sheet is name and birthday only (`reference/immich/mobile/lib/presentation/widgets/people/person_option_sheet.widget.dart:21-30`). There is no merge, hide, favorite, or delete control. A search of `mobile/` finds `mergePerson`, `updatePeople`, `deletePerson`, and `reassignFaces` nowhere.

**Faces on an asset.** The viewer details sheet mounts `PeopleDetails` for every asset (`reference/immich/mobile/lib/presentation/widgets/asset_viewer/asset_details.widget.dart:49`). A remote asset watches `Store.people.forAsset` (`reference/immich/mobile/lib/presentation/widgets/asset_viewer/asset_details/people_details.widget.dart:26-31`). A local-only asset draws nothing (`people_details.widget.dart:27-29`). The query returns each non-hidden person once, for a visible face on that asset with `deleted_at` null (`person.dart:22-37`, `data/store/person.dart:21-24`). The sheet draws the name, the age at the asset's `createdAt` when `birthDate` is set, and the face thumbnail (`people_details.widget.dart:53-76`, `103-162`). A tap opens that person's page. It does not call `GET /api/faces`. `ApiService` never builds a faces client (`api.service.dart:18-42`, `56-79`). A search of `mobile/` finds `getFaces`, `createFace`, and `deleteFace` nowhere.

The bounding box is stored and not drawn. `AssetFaceV3` writes `id`, `assetId`, `personId`, `imageWidth`, `imageHeight`, `boundingBoxX1`, `boundingBoxY1`, `boundingBoxX2`, `boundingBoxY2`, `sourceType`, `deletedAt`, and `isVisible` (`sync_stream.repository.dart:845-866`, `sync_stream.service.dart:328-330`). `AssetFaceDeleteV1` deletes by face id (`sync_stream.repository.dart:876-880`). A search of `mobile/lib` for `boundingBox` finds the table and that writer only. The screens that show a person read `personId`, `isVisible`, and `deletedAt`. They do not read the box, the image size, or `sourceType`. A face with a null `personId` cannot appear, because both queries join through `person_id`.

**Name and birthday.** Saving a name calls `PersonStore.updateName`, then writes the submitted string into SQLite (`reference/immich/mobile/lib/presentation/widgets/people/person_edit_name_modal.widget.dart:29-33`, `data/store/person.dart:55-57`). Saving a birthday does the same with the picked calendar day (`reference/immich/mobile/lib/presentation/widgets/people/person_edit_birthday_modal.widget.dart:31-36`, `data/store/person.dart:61-63`). Both are `PUT /api/people/{id}`. The local write runs only after the call returns. The response is parsed and then discarded. The stored `updatedAt` is `DateTime.now()`, not the response (`person.dart:72-80`). The person page copies the new name into its widget state only when the name is non-empty (`person.page.dart:37-40`). An empty name is still sent. A throw shows a toast and leaves SQLite as it was (`person_edit_name_modal.widget.dart:35-47`). The app never sends `isHidden`, `isFavorite`, `color`, `featureFaceAssetId`, or `userId`.

**Thumbnail.** Every person avatar is `GET /api/people/{id}/thumbnail`, built by `getFaceThumbnailUrl` (`reference/immich/mobile/lib/utils/image_url_builder.dart:23-26`). Call sites are the library card, the people grid, the person app bar, the asset details sheet, and the search people picker (`library.page.dart:190-191`, `people_collection.page.dart:103-104`, `person_sliver_app_bar.dart:230-231`, `people_details.widget.dart:122-123`, `reference/immich/mobile/lib/widgets/search/search_filter/people_picker.dart:26`, `83-84`). The picker filters the same local list. It does not call `GET /api/search/person`. `updatedAt` is only the `c` cache-buster query. The image bytes are not parsed as JSON.

**Search.** The search tab is `SearchRoute`, the second child of the shell (`tab_shell.page.dart:80`, `router.dart:126`). An empty filter draws quick links and does not search (`reference/immich/mobile/lib/presentation/pages/search/search.page.dart:79-90`, `715-718`, `893-914`). Submitting text, or applying a filter, clears the in-memory page and searches page 1 (`search.page.dart:79-90`, `reference/immich/mobile/lib/presentation/pages/search/paginated_search.provider.dart:46-53`). Hits stay in that notifier. They are not written to SQLite (`paginated_search.provider.dart:60-63`, `reference/immich/mobile/lib/infrastructure/repositories/timeline.repository.dart:271-281`). The grid is `Timeline` with `GroupAssetsBy.none` over that list (`search.page.dart:788-807`).

Which route runs is decided in `SearchApiRepository.search`. A non-empty `context`, or a non-empty `assetId`, is `POST /api/search/smart`. Anything else that is not an empty filter is `POST /api/search/metadata` (`reference/immich/mobile/lib/infrastructure/repositories/search_api.repository.dart:20-53`). Context is the default text mode when stored server features say `smartSearch`. Otherwise the default is filename (`search.page.dart:44-49`, `reference/immich/mobile/lib/models/server_info/server_features.model.dart:14-24`). The context menu item is hidden without that flag (`search.page.dart:537-556`, `reference/immich/mobile/lib/widgets/common/feature_check.dart:29-36`). Filename, description, and OCR text modes clear the other three text fields and submit (`search.page.dart:494-498`). OCR text mode is shown only when stored features say `ocr` (`search.page.dart:594-611`). The people, place, camera, date, media-type, rating, and display chips are the same body, on whichever route the text mode selected. The people chip reads the local people list (`people_picker.dart:26`).

"View similar photos" is on a remote asset outside the locked view (`reference/immich/mobile/lib/utils/action_button.utils.dart:145-147`, `199-201`). It does not check `smartSearch`. It sets `assetId` to that asset, clears the other filters, and opens search (`reference/immich/mobile/lib/presentation/actions/similar_photos.action.dart:21-40`). That is smart search with `queryAssetId` and no `query`. A later text submit uses `copyWith` and does not clear `assetId` (`search.page.dart:494-498`). While `assetId` is set, the repository stays on smart search, and filename, description, and OCR text are not fields of that body (`search_api.repository.dart:20-50`).

The mapper keeps `id`, `originalFileName`, `checksum`, `fileCreatedAt`, `updatedAt`, `createdAt` (stored as `uploadedAt`), `ownerId`, `visibility`, `duration`, `height`, `width`, `isFavorite`, `livePhotoVideoId`, `thumbhash`, `type`, `stack.id`, and `isEdited` (`reference/immich/mobile/lib/extensions/asset_extensions.dart:7-26`). `localId` is set to null, so the tile is the remote cloud icon even when a device copy exists (`asset_extensions.dart:23`, `reference/immich/mobile/lib/domain/models/asset/remote_asset.model.dart:64`, `reference/immich/mobile/lib/presentation/widgets/images/thumbnail_tile.widget.dart:162-174`). The tile also reads `isFavorite`, video `durationMs`, live photo (`livePhotoVideoId`), animated image (`durationMs > 0` on an image), and `stackId` (`thumbnail_tile.widget.dart:187-198`, `302-336`, `remote_asset.model.dart:44-56`). `thumbHash` is the placeholder when it is non-null (`reference/immich/mobile/lib/presentation/widgets/images/thumbnail.widget.dart:44-47`). The thumbnail request is `GET /api/assets/{id}/thumbnail` through `RemoteImageProvider.thumbnail` (`reference/immich/mobile/lib/presentation/widgets/images/image_provider.dart:206-223`). That is the library thumbnail route. It is not a search route. `name` is copied onto the row and not drawn on the tile. `people` and `exifInfo` on the hit are not read. `nextPage` is `int.parse` of the string (`reference/immich/mobile/lib/domain/services/search.service.dart:18-25`, `reference/immich/mobile/lib/extensions/string_extensions.dart:29-31`). The flat search this app sends returns that string as the next page number, or null (`reference/immich/server/src/services/search.service.ts:99-113`, `184-197`, `369-383`). `nextCursor` is not read. An empty `items` array, or a throw, becomes a null result and the page number is left unchanged (`search.service.dart:18-29`, `paginated_search.provider.dart:55-57`), so the next scroll asks for the same page again (`search.page.dart:93-94`, `730-741`).

Camera and location sheets call `GET /api/search/suggestions` for country, state, city, camera make, and camera model (`reference/immich/mobile/lib/widgets/search/search_filter/camera_picker.dart:24-32`, `reference/immich/mobile/lib/widgets/search/search_filter/location_picker.dart:26-54`, `reference/immich/mobile/lib/providers/search/search_filter.provider.dart:19-33`). Those strings fill dropdowns. They are not search hits. `getExploreData` and `getAllPlaces` are marked unused and have no other caller under `mobile/` (`reference/immich/mobile/lib/services/search.service.dart:42-60`). A search of `mobile/` finds `searchRandom`, `searchLargeAssets`, `searchPlaces`, and `searchAssetStatistics` nowhere.

**OCR.** The viewer shows it. For an image, the bottom bar mounts `OcrToggleButton` when the local OCR list for that remote asset is non-empty (`reference/immich/mobile/lib/presentation/widgets/asset_viewer/bottom_bar.widget.dart:96`, `reference/immich/mobile/lib/presentation/widgets/asset_viewer/ocr_toggle_button.widget.dart:14-15`). The toggle flips `showingOcr` (`reference/immich/mobile/lib/providers/asset_viewer/asset_viewer.provider.dart:113`). Searching by OCR text is the metadata search below, not a second OCR route.

## Calls

### `PUT /api/people/{id}`

- When: saving a person's name, from the people grid, the person app bar, the person option sheet, or the asset details sheet. Saving a birthday, from the person app bar or the option sheet. Each save is its own request. A field that caller does not pass is not set on the DTO.
- Method and path: `PUT /api/people/{id}`. No query. Operation `updatePerson` (`immich-openapi-specs.json:10408-10411`). Authenticated. Session cookie. The OpenAPI operation is the deprecated `PUT`. `PATCH /api/people/{id}` is `ApiExcludeEndpoint` and is not the operation the app calls (`person.controller.ts:111-128`, `130-138`).
- Request: JSON `PersonUpdateDto`. Every property is optional, and at least one field other than `userId` must be set (`reference/immich/server/src/dtos/person.dto.ts:17-43`, `immich-openapi-specs.json:25560-25599`). Name save sets `name` to the field text, including an empty string, and leaves `birthDate` absent (`reference/immich/mobile/lib/data/server/person.dart:14-20`, `person_edit_name_modal.widget.dart:72`). Birthday save sets `birthDate` to `DateTime.utc` of that calendar day and leaves `name` absent (`person.dart:15-18`). The schema format is `date` (`person.dto.ts:20-26`). The app does not set `isHidden`, `isFavorite`, `color`, `featureFaceAssetId`, or `userId`. The server writes the fields it was given and returns the person (`reference/immich/server/src/services/person.service.ts:241-291`).
- Response fields the app requires: `checkNull` throws if the body is null (`reference/immich/mobile/lib/data/server/api_repository.dart:6-11`). The mapper reads `id`, `name`, `birthDate`, and `updatedAt` (`person.dart:24-25`). `updatedAt` is optional and is read with `orElse(null)`. The caller then ignores the mapped object. Required even though the mapper does not use them: `isHidden` and `thumbnailPath`. `birthDate` is required and nullable, so JSON null does not throw and a missing key does. `otherPeople`, `sharedBy`, and `sharedWith` are required, but a null is replaced with `[]` before parse (`openapi_patching.dart:46`). A non-empty `otherPeople` item requires `birthDate`, `name`, `role`, and `sharedById`. A non-empty `sharedBy` or `sharedWith` item requires `avatarColor`, `email`, `id`, `name`, `profileChangedAt`, `profileImagePath`, and `role` (`immich-openapi-specs.json:25433-25543`, `25640-25688`). The app reads none of those. Server status is 200 (`immich-openapi-specs.json:10434-10441`). A throw skips the local name or birthday write.
- Source: `data/server/person.dart:14-25`, `data/store/person.dart:55-63`. Server: `person.controller.ts:111-128`, `person.service.ts:241-291`, `person.dto.ts:109-138`.

### `GET /api/people/{id}/thumbnail`

- When: a person avatar is painted. The library card, the people grid, the person app bar, the asset details sheet, and the search people picker. It is not a generated-client call. The widget asks `RemoteImageProvider` for the URL, and the native image loader performs the GET (`reference/immich/mobile/lib/presentation/widgets/images/remote_image_provider.dart:34-47`, `reference/immich/mobile/lib/infrastructure/loaders/remote_image_request.dart:17-22`).
- Method and path: `GET /api/people/{id}/thumbnail`. Operation `getPersonThumbnail` (`immich-openapi-specs.json:10701-10704`). Authenticated. Session cookie. The spec lists no query parameter (`immich-openapi-specs.json:10705-10716`). When the local person has `updatedAt`, the app adds `c` as that timestamp in milliseconds (`image_url_builder.dart:23-26`). It does not add a size.
- Request: no body. Android's image fetch adds `User-Agent` `immich-android/<version>`, the saved custom headers, `Cookie` from the persistent jar, and `Authorization: Basic` only when the URL has userinfo (`reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/images/RemoteImagesImpl.kt:269-273`, `reference/immich/mobile/android/app/src/main/kotlin/app/alextran/immich/core/HttpClientManager.kt:56`, `276-284`, `315-322`). iOS uses the shared cookie store and `User-Agent` `immich-ios/<version>` plus saved headers (`reference/immich/mobile/ios/Runner/Images/RemoteImagesImpl.swift:38-46`, `reference/immich/mobile/ios/Runner/Core/URLSessionManager.swift:54-57`, `147-156`). This GET does not go through `ApiClient`, so it does not add `deviceModel` or `deviceType`.
- Response fields the app requires: none as JSON. The body is image bytes. The server sends the person's thumbnail file, or 404 when there is no path (`person.service.ts:207-222`, `person.controller.ts:164-178`). A decode failure leaves the avatar empty. The app does not read `thumbnailPath` from any person JSON to build this URL. The id in the path is the local person id.
- Source: `image_url_builder.dart:23-26`, `remote_image_provider.dart:12-47`, `remote_image_request.dart:11-22`. Server: `person.controller.ts:164-178`, `person.service.ts:207-222`.

### `POST /api/search/smart`

- When: the search page submits context text, or any non-empty filter while `context` or `assetId` is set. "View similar photos" is this call with `queryAssetId` and no `query`. A filename, description, or OCR submit does not use this route unless `assetId` is still set from similar photos.
- Method and path: `POST /api/search/smart`. No query. Operation `searchSmart` (`immich-openapi-specs.json:12681-12684`). Authenticated. Session cookie. Server status is 200 (`search.controller.ts:82-91`).
- Request: JSON `SmartSearchDto`. No property is required (`immich-openapi-specs.json` schema `SmartSearchDto`). The app sets `query` when `context` is non-null, `queryAssetId` when `assetId` is non-null, and `language` when the filter has one. The search page always sets `language` to `{languageCode}-{countryCode}` (`search.page.dart:61`). Similar photos leaves it null, so it is absent (`similar_photos.action.dart:28-37`). It always sets `visibility` to `archive` when the display filter says archive, otherwise `timeline`. It always sets `personIds` to the selected ids, including `[]`. It always sets `page` to the current page, starting at 1, and `size` to `100` (`search_api.repository.dart:22-49`, `paginated_search.provider.dart:30`). `country`, `state`, `city`, `make`, `model`, `takenAfter`, and `takenBefore` are present only when that filter is set. `rating` is absent when the rating option is none, present null for unrated, and present `1` through `5` otherwise (`reference/immich/mobile/lib/utils/option.dart:68-71`, `search_filter.model.dart:33-35`). `isFavorite` and `isNotInAlbum` are present `true` only when that display flag is on. Otherwise they are absent, not `false`. `tagIds` is present when the filter's list is non-null. The search page starts it at `[]`. Similar photos leaves it null. `type` is `IMAGE` or `VIDEO` when the media filter says so, and absent for the other type (`search_api.repository.dart:12-18`). The app does not set `filter`, `orderBy`, `cursor`, or any other flat field. Because `filter` is absent, the server stays on the flat search and returns `nextPage`, not `nextCursor` (`search.service.ts:168-197`). The app does not send filename, description, or `ocr` on this body. Those fields exist on the schema and are not set here (`search.dto.ts:67`, `390-399`).
- Response fields the app requires: a non-null `SearchResponseDto`. Both `albums` and `assets` are required (`immich-openapi-specs.json:27582-27594`). The app reads `assets.items` and `assets.nextPage` (`search.service.dart:18-24`). `items` empty returns null and draws no new hits. `nextPage` is a nullable string. A numeric string becomes the next page. Null stops further pages. `int.parse` throws on a non-numeric string, the search future returns null, and the current page is kept. On this flat request the server sends `(page + 1)` as a decimal string, or null (`search.service.ts:197`). `assets` also requires `count`, `facets`, `total`, and `nextCursor` (`SearchAssetResponseDto`). `nextCursor` is nullable. A null is filled in before parse and is not read. `facets` is a required array. Each facet requires `fieldName` and `counts`, and each count requires `count` and `value`. `albums` requires `total`, `count`, `items`, and `facets`. The app reads no album field. The server sends albums as zeros and empty arrays (`search.service.ts:374-383`). Each hit is `AssetResponseDto`. `toDto` reads the fields listed in the sequence. Required on that DTO even when `toDto` does not read them: `fileModifiedAt`, `hasMetadata`, `isArchived`, `isOffline`, `isTrashed`, `localDateTime`, and `originalPath`. `duration`, `height`, `width`, and `thumbhash` are required and nullable. `visibility`, `createdAt`, and `isEdited` are filled when null before parse (`openapi_patching.dart:37`). `livePhotoVideoId` and `stack` are not required. A present `stack` requires `id`, `primaryAssetId`, and `assetCount`, and the app reads `id` only (`asset_extensions.dart:25`). `people` and `exifInfo` are optional. The app does not read them. A present `people` item is a `PersonResponseDto` and still has to parse.
- Source: `search_api.repository.dart:20-50`, `domain/services/search.service.dart:14-29`, `asset_extensions.dart:7-26`. ### `POST /api/search/metadata`

- When: a search that is not empty and has neither a non-empty `context` nor an `assetId`. That is filename text, description text, OCR text, or a filter-only search. OCR text is this call. It is not `GET /api/assets/{id}/ocr`.
